# <span style="color:orange">  Valid Palindrome </span>

## 1. Problem Statement
LeetCode 125 / NeetCode "Valid Palindrome" (`is-palindrome`). Given a string `s`, return `true` if it is a palindrome after ignoring case and all non-alphanumeric characters (alphanumeric = `A-Z`, `a-z`, `0-9`), otherwise `false`.
Constraints: `1 <= s.length <= 1000`, `s` contains only printable ASCII characters. Target: O(n) time, O(1) space.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public boolean isPalindrome(String st) {
        
        int s=0;int e= st.length()-1;
        st=st.toLowerCase();
        while(s<e){
            if(!checkChar(st.charAt(s))){ s++; continue;}
            if(!checkChar(st.charAt(e))){ e--; continue;}
            if(st.charAt(s)!=st.charAt(e))return false;
            s++; e--;
        }

        return true;
    }

    boolean checkChar(char c){

        return ('a'<= c && c<='z') || (c>='0' && c<='9');
    }
}
```

Lowercase the whole string, then use two pointers from both ends moving inward. Skip a non-alphanumeric character on either side, otherwise compare the two characters and return `false` on a mismatch.

## 3. Complexity
- Time: O(n)
- Space: O(n) because `toLowerCase()` creates a new string (Java strings are immutable). Not the O(1) target.
- Correct on all cases I traced (`"Was it a car or a cat I saw?"`, `"tab a cat"`, `".,"`, single character).

## 4. What I Missed
- **Hidden O(n) space:** `st.toLowerCase()` allocates a full copy. The two-pointer idea is O(1) space, but the normalization step quietly removes that. Lowercase one character at a time with `Character.toLowerCase(c)` instead.
- **Locale pitfall:** `String.toLowerCase()` uses the default locale. In a Turkish locale `'I'` becomes `'ı'` (U+0131), which `checkChar` rejects, so the character would be silently skipped. `Character.toLowerCase(char)` (or `toLowerCase(Locale.ROOT)`) avoids this.
- Reassigning the parameter (`st = st.toLowerCase()`) hides the allocation; parameter `st` and pointers `s`/`e` are confusing names.
- Did not state why the loop is O(n): each pointer only moves inward and never backs up, so the total pointer moves are at most n.
- Helper `checkChar` is a non-static method with a vague name (`isAlphanumeric`). Behavior is correct for the ASCII constraint.
- Handled correctly but worth stating out loud: all non-alphanumeric input (e.g. `".,"`) returns `true` (empty string is a palindrome), and single character returns `true`.

## 5. Optimal Approach
Two pointers from both ends. At each step skip non-alphanumeric characters in place (with `l < r` guards), compare the two characters after lowercasing them individually, and move both inward. No copy of the string is ever made, so O(n) time and O(1) space.

## 6. Optimal Java Code

```java
class Solution {
    public boolean isPalindrome(String s) {
        int l = 0, r = s.length() - 1;
        while (l < r) {
            while (l < r && !isAlphanumeric(s.charAt(l))) l++;
            while (l < r && !isAlphanumeric(s.charAt(r))) r--;
            if (Character.toLowerCase(s.charAt(l)) != Character.toLowerCase(s.charAt(r))) {
                return false;
            }
            l++;
            r--;
        }
        return true;
    }

    private boolean isAlphanumeric(char c) {
        return (c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z') || (c >= '0' && c <= '9');
    }
}
```

## 7. Quick Revision
Palindrome = mirrored positions are equal, so use two pointers from both ends moving inward, skipping non-alphanumerics in place.
Normalize case per character with `Character.toLowerCase`, never by building a new string (Java strings are immutable, so that is hidden O(n) space).

## 8. Pattern
- Primary: Two Pointers (opposite ends)
- Secondary: In-place skipping/filtering, String processing

# <span style="color:orange">  Two Sum II </span>

## 1. Problem Statement
LeetCode 167 / NeetCode "Two Integer Sum II" (Two Sum II - Input Array Is Sorted). Given a 1-indexed array `numbers` sorted in non-decreasing order and an integer `target`, return the 1-indexed positions `[index1, index2]` (with `index1 < index2`) of the two numbers that add up to `target`. The same element cannot be used twice. Exactly one solution is guaranteed. **Use only O(1) extra space.**
Constraints (per LeetCode 167; the NeetCode limits may differ slightly): values and target in about `[-1000, 1000]`.
Note: the NeetCode page itself could not be opened (the submission-history link is login-gated), so the statement above is the standard LeetCode 167 version.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public int[] twoSum(int[] nums, int t) {

        int ans[]= new int[2];
        int s=0; int e= nums.length-1;

        while(s<e){
            int sum =nums[s]+nums[e];
             if(sum==t){ ans[0]=s+1;ans[1]=e+1; break;}
             
             if(sum>t)e--;
             else s++;

        }
        return ans;    
    }
}
```

Two pointers at both ends. If the sum equals the target, store the 1-indexed positions and stop. If the sum is too large move the right pointer left; if too small move the left pointer right.

## 3. Complexity
- Time: O(n)
- Space: O(1) extra (the 2-element result array is constant size)
- Correct and optimal. Hand-checked on `[2,7,11,15]` target 9 and on duplicates `[2,2,5,7]` target 4.

## 4. What I Missed
No algorithmic mistakes. Remaining gaps:
- **Unstated invariant (the real interview question):** if `sum < target`, `nums[s]` plus any remaining partner is at most `nums[s] + nums[e]`, because `nums[e]` is the largest remaining value, so `nums[s]` cannot be part of the answer and is safe to discard. The symmetric argument discards `nums[e]` when `sum > target`. The answer pair is therefore never discarded.
- **Misleading fallback:** if no pair were found the code returns `[0, 0]`, which looks like a valid answer. The problem guarantees a solution, so make the unreachable path explicit (`new int[0]`).
- Allocate-then-fill-then-`break` is clumsier than returning `new int[]{s + 1, e + 1}` directly.
- Did not mention the alternatives: a hash map (Two Sum I) is O(n) time but O(n) space, which violates the O(1) space requirement; binary search for each complement is O(n log n).
- `int` sum is safe here because values are small; if values could span the full int range, use `long` for the sum.
- Terse names (`s`, `e`, `t`, `nums`) make the invariant harder to read in an interview.

## 5. Optimal Approach
Two pointers `l = 0`, `r = n - 1`. Compare `numbers[l] + numbers[r]` with `target`. Equal: return `[l + 1, r + 1]`. Too small: `l++` (the left value can never work with anything remaining). Too large: `r--`. Each step permanently discards one element, so at most `n - 1` steps. O(n) time, O(1) space.

## 6. Optimal Java Code

```java
class Solution {
    public int[] twoSum(int[] numbers, int target) {
        int l = 0, r = numbers.length - 1;
        while (l < r) {
            int sum = numbers[l] + numbers[r];
            if (sum == target) return new int[]{l + 1, r + 1};
            if (sum < target) l++;
            else r--;
        }
        return new int[0]; // unreachable: exactly one solution is guaranteed
    }
}
```

## 7. Quick Revision
Sorted array + "find a pair with sum X" means two pointers from both ends: sum too small, so the left value can never work (the right end is already its best partner), so `l++`; too big, so `r--`.
O(n) time, O(1) space, which is why it beats the Two Sum I hash map when O(1) space is required.

## 8. Pattern
- Primary: Two Pointers (opposite ends, sorted array)
- Secondary: Binary search per element (O(n log n) alternative), Hash map (unsorted Two Sum I variant)

# <span style="color:orange">  3Sum </span>

## 1. Problem Statement
LeetCode 15 / NeetCode "Three Integer Sum". Given an integer array `nums`, return all triplets `[nums[i], nums[j], nums[k]]` with distinct indices `i`, `j`, `k` such that the sum is 0. The output must not contain duplicate triplets; order does not matter.
Constraints: `3 <= nums.length <= 3000`, `-10^5 <= nums[i] <= 10^5`. Target: O(n^2) time, O(1) extra space.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {

        List<List<Integer>> ans =new ArrayList<>();
        int n=nums.length;

         Arrays.sort(nums);

          for(int i=0;i<n;){
            int c= nums[i];

            List<List<Integer>> tl= twoSum(nums,i+1,n-1,0 - c);
            ans.addAll(tl);

            while(i<n && c==nums[i])i++;
          }  

        return ans;
    }

    public List<List<Integer>> twoSum(int[] nums,int s,int e,int t ) {

        List<List<Integer>> ans  = new ArrayList<>();
        while(s<e){
            int c1=nums[s];
            int c2=nums[e];
            int sum =c1+c2;
             if(sum==t){ 
                    List<Integer> t1 = new ArrayList<>();
                    t1.add(0-t);
                    t1.add(c1);
                    t1.add(c1);
                    ans.add(t1);
                    
                    while(s+1<nums.length && c1==nums[s])s++;
                    while(e -1>=0 && c2==nums[e])e--;
                }
             else if(sum>t)e--;
             else s++;

        }

        return ans;   
    }
}
```

Sort the array. For each distinct first value `c`, run a two-pointer Two Sum II on the elements to its right with target `-c`. On a match, record the triplet and skip duplicates of both pointers.

## 3. Complexity
- Time: O(n^2) (sort O(n log n) + n two-pointer passes of O(n))
- Space: O(1) auxiliary besides the output (plus sort stack), though it builds extra intermediate lists.
- The algorithm and structure are right, but the code is **incorrect** because of one bug (below).

## 4. What I Missed
- **Bug: the third element is `c1` instead of `c2`.** `t1.add(c1); t1.add(c1);` records `[first, c1, c1]`. Traced on Example 1 (`[-1,0,1,2,-1,-4]`, sorted `[-4,-1,-1,0,1,2]`): at `i=1` it finds `-1 + 2 = 1` and records `[-1,-1,-1]` (should be `[-1,-1,2]`), then `0 + 1 = 1` and records `[-1,0,0]` (should be `[-1,0,1]`). Output `[[-1,-1,-1],[-1,0,0]]`, so it fails the first sample.
- Never dry-ran the first example. This is not a rare edge case; it fails the given sample.
- Confusing names `t` (target) vs `t1` (triplet) vs `tl`; reconstructing the first element as `0 - t` instead of passing it in.
- Duplicate-skip loop guards (`s+1 < nums.length`, `e-1 >= 0`) protect array bounds rather than the real condition (`s < e`). It happens to work, but guards the wrong thing.
- No early exit: after sorting, once `nums[i] > 0` three non-negative values cannot sum to 0, so the loop can stop.
- Helper builds and returns a new list per `i`, then `addAll`; adding directly to the result is simpler.
- Good (keep): sort, then fix the first element and skip duplicates of it, starting the pair at `i + 1` so a repeated value can still pair with itself (e.g. `[-1,-1,2]`).

## 5. Optimal Approach
Sort. For each index `i` (skipping values equal to the previous one, and stopping at `nums[i] > 0`), run two pointers `l = i + 1`, `r = n - 1`. Sum too small: `l++`; too large: `r--`; zero: record the triplet, move both pointers, and skip duplicate values at `l`. O(n^2) time, O(1) extra space. A hash-set variant is also O(n^2) but needs O(n) space and messier deduplication, so two pointers is better.

## 6. Optimal Java Code

```java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> res = new ArrayList<>();
        Arrays.sort(nums);
        int n = nums.length;

        for (int i = 0; i < n - 2; i++) {
            if (nums[i] > 0) break;                          // three positives cannot sum to 0
            if (i > 0 && nums[i] == nums[i - 1]) continue;   // skip duplicate first element

            int l = i + 1, r = n - 1;
            while (l < r) {
                int sum = nums[i] + nums[l] + nums[r];
                if (sum < 0) l++;
                else if (sum > 0) r--;
                else {
                    res.add(Arrays.asList(nums[i], nums[l], nums[r]));
                    l++;
                    r--;
                    while (l < r && nums[l] == nums[l - 1]) l++;   // skip duplicate second element
                }
            }
        }
        return res;
    }
}
```

## 7. Quick Revision
3Sum = fix one number `x` after sorting, then solve Two Sum II (two pointers) on the rest with target `-x`.
Sorted order makes duplicates adjacent: skip repeated first elements, and after a match skip repeated values at the left pointer. Dry-run Example 1 before submitting.

## 8. Pattern
- Primary: Sorting + Two Pointers (reduction of k-Sum to (k-1)-Sum)
- Secondary: Duplicate skipping on sorted data, Hash set (O(n) space alternative)

# <span style="color:orange">  Container With Most Water </span>

## 1. Problem Statement
LeetCode 11 / NeetCode "Container With Most Water" (`max-water-container`). Given an integer array `heights`, choose any two bars to form a container and return the maximum amount of water it can store. Area for bars `i < j` is `min(heights[i], heights[j]) * (j - i)`.
Constraints: `2 <= heights.length <= 100,000`, `0 <= heights[i] <= 10,000`. Target: O(n) time, O(1) space.

## 2. My Approach
Two submissions (both unmodified).

**Attempt 1: brute force (with an equality break)**

```java
class Solution {
    public int maxArea(int[] nums) {

        int ans = Integer.MIN_VALUE;
        int n =nums.length;

        for(int i=0;i<n;i++){
            int j=n-1;

            while(j>i){
                
                int minHeight = Math.min(nums[j],nums[i]);
                int dis = j-i;

                ans = Math.max(ans, minHeight * dis);
                if(nums[j]==nums[i])break;
                j--;
            }
        }
        
        
        return ans;
    }
}
```

For each `i`, scan `j` from the right end down to `i + 1`, track the best area, and stop early when the two heights are equal.

**Attempt 2: two pointers (optimal)**

```java
class Solution {
    public int maxArea(int[] nums) {

        int ans = Integer.MIN_VALUE;
        int n =nums.length;
        int l= 0;
        int r =n-1;

        while(l<r){

            int lh= nums[l];
            int rh =nums[r];

            // calculate min 
            int min = Math.min(lh,rh);
            // calculate dis 
            int d = r-l;
            // current container size will be (min * d)
            ans = Math.max(ans,min*d);

            // move smallest pointer only as we need max area
            if(lh<rh) l++;
            else r--;
            // in case of both heigth are samw than it doesnt matter which pointer you are moving
            // here we are moving right 
        }
        
        
        
        return ans;
    }
}
```

Start with the widest container (`l = 0`, `r = n - 1`), record the area, then move only the shorter pointer inward and repeat.

## 3. Complexity
- Attempt 1: O(n^2) time (the equality `break` only prunes the tie case), O(1) space. With n up to 10^5 this is about 5 x 10^9 pair checks in the worst case, so it will likely time out.
- Attempt 2: O(n) time, O(1) space. Correct and optimal. Max area is at most about 10^9, which fits in `int`.

## 4. What I Missed
- **Key insight (from my own note): move only the shorter pointer and keep the taller one.** Moving both is wrong. Counterexample `[3, 9, 1, 9]`: the correct answer is 18 (bars 1 and 3), but moving both pointers after `(0, 3)` jumps to `(1, 2)` and never evaluates `(1, 3)`, returning 9.
- **Why the shorter pointer is safe to discard:** any container that keeps the shorter bar and moves the other end inward has height <= the shorter bar's height and a smaller width, so its area <= the area already recorded. That bar is finished.
- **Why the taller pointer is not safe to discard:** it may still pair with another tall bar further inside for a bigger area.
- **The brute-force `break` hints at the answer.** It stops only when `nums[j] == nums[i]`, but the correct condition is `nums[j] >= nums[i]`: once the right bar is at least as tall as the left bar, no closer `j` can beat it for this `i`. That "this bar is exhausted" idea is exactly the two-pointer rule.
- Tie case (`lh == rh`): moving either pointer is fine, since both bars are exhausted (moving both would also be safe in this one case, but is unnecessary).
- Minor: initializing `ans` with `Integer.MIN_VALUE` works but `0` is enough (heights are non-negative, `n >= 2`); the array is named `nums` instead of `heights`.

## 5. Optimal Approach
Start with the widest container. The shorter bar caps the height, and pairing it with any closer bar only reduces width, so it can never improve the answer. Discard it by moving its pointer inward, and repeat. Every step removes one bar, so the loop runs at most n - 1 times: O(n) time, O(1) space.

## 6. Optimal Java Code

```java
class Solution {
    public int maxArea(int[] heights) {
        int l = 0, r = heights.length - 1;
        int best = 0;
        while (l < r) {
            int h = Math.min(heights[l], heights[r]);
            best = Math.max(best, h * (r - l));
            if (heights[l] < heights[r]) l++;   // shorter bar is exhausted
            else r--;                           // equal heights: either side is fine
        }
        return best;
    }
}
```

## 7. Quick Revision
Start with the widest container; the shorter bar limits the height, and pairing it with any closer bar only loses width, so it can never do better: move the shorter pointer inward.
Never move the taller pointer, and never both (except in a tie). Each step discards one bar, so O(n).

## 8. Pattern
- Primary: Two Pointers (opposite ends) with a greedy discard argument
- Secondary: Brute force with pruning (the pruning leads to the pointer rule), Maximizing a product of two competing factors (width vs height)

# <span style="color:orange">  Trapping Rain Water </span>

## 1. Problem Statement
LeetCode 42 / NeetCode "Trapping Rain Water". Given non-negative integers `height`, each the height of a bar of width 1, return the total amount of water trapped between the bars after raining.
Example: `[0,2,0,3,1,0,1,3,2,1]` -> `9`.
Constraints: `1 <= height.length <= 20,000`, `0 <= height[i] <= 100,000`. Recommended: O(n) time, O(n) space or better.

## 2. My Approach
Two submissions (both unmodified).

**Attempt 1: prefix max and suffix max arrays**

```java
class Solution {
    public int trap(int[] nums) {

        int ans =0;
        int n= nums.length;

        int lm[]=new int[n];
        int rm[]=new int[n];
       
        lm[0]=nums[0];
       
       for(int i=1;i<n;i++)
        lm[i]=Math.max(lm[i-1],nums[i]);

        rm[n-1]=nums[n-1];

        for( int i=n-2;i>=0;i--)
           rm[i] =Math.max(rm[i+1],nums[i]);

        for(int i=0;i<n;i++){
            if(nums[i]<lm[i] && nums[i]<rm[i]){
                int min =Math.min(lm[i],rm[i]);
                ans+=(min-nums[i]);
            }
            
        }    


        return ans;
    }
}
```

`lm[i]` is the tallest bar at or left of `i`, `rm[i]` the tallest at or right of `i`. Water above bar `i` is `min(lm[i], rm[i]) - nums[i]`.

**Attempt 2: two pointers with running maxima (optimal)**

```java
class Solution {
    public int trap(int[] nums) {
        
            int ans=0;
            int n= nums.length;
            int lm=0,rm=0,l=0,r=n-1;

           while(l<r){

                if(nums[l]<=nums[r]){
                       if(lm>nums[l])ans+=(lm-nums[l]);
                       else lm =nums[l] ;
                    l++ ;
                }
                else{
                    if(rm>nums[r]) ans+=(rm-nums[r]);
                    else rm=nums[r];
                    r--;
                }
           } 
 
        return ans;
    }
}
```

Two pointers from both ends with running maxima `lm` and `rm`. Always process the side whose current bar is lower, using that side's own running max as the water level.

## 3. Complexity
- Attempt 1: O(n) time, O(n) space (two extra arrays). Meets the recommended complexity.
- Attempt 2: O(n) time, O(1) space. Optimal. (It removes both arrays, not just `lm`.)
- Answer fits in `int`: at most about 19,998 x 100,000 = ~2 x 10^9 < 2,147,483,647 (close to the limit).

## 4. What I Missed
- **The core formula was not formed first:** water above bar `i` = `min(tallest bar to the left, tallest bar to the right) - height[i]`. Everything else (arrays, pointers) is just a way to compute this fast.
- Attempt 1: the `if (nums[i] < lm[i] && nums[i] < rm[i])` guard is redundant. `lm[i]` and `rm[i]` include `nums[i]` itself, so `min(lm[i], rm[i]) - nums[i]` is never negative; just add it.
- Attempt 2: no stated reason it is correct (see Optimal Approach). Also relies on `lm = rm = 0` being a safe start, which holds only because heights are non-negative.
- The loop stops at `l == r` without processing that bar: it is the tallest bar, which holds no water (every earlier step passes the smaller bar of the pair, so the survivor is the maximum).
- Naming (`nums`, `lm`, `rm`) hides meaning; `height`, `leftMax`, `rightMax` read better.
- Monotonic stack also solves it in O(n) time and space, but is no better than the two-pointer solution here.

## 5. Optimal Approach
**Intuition (per bar):** water sits above a bar up to the lower of its two walls (the tallest bar on its left and on its right), because it spills over the lower one. So `water[i] = min(maxLeft, maxRight) - height[i]`, and the answer is the sum over all bars. Brute force rescans left and right for every bar (O(n^2)); prefix/suffix max arrays remove that repeated work (O(n) time, O(n) space).

**Intuition (two pointers):** only the smaller of `maxLeft` and `maxRight` matters, so we do not need both exactly. Keep `l`, `r` and running maxima `leftMax`, `rightMax`. If `height[l] <= height[r]`, the right side has a wall at least as tall as everything passed so far on the left, so the left side is the bottleneck: water at `l` is `leftMax - height[l]` (if positive), then `l++`. Otherwise do the mirror on the right. Always process the lower side. Same "act on the shorter side" instinct as Container With Most Water.

## 6. Optimal Java Code
Equivalent to my Attempt 2, with clearer names:

```java
class Solution {
    public int trap(int[] height) {
        int l = 0, r = height.length - 1;
        int leftMax = 0, rightMax = 0, water = 0;
        while (l < r) {
            if (height[l] <= height[r]) {            // left is the lower end
                if (height[l] >= leftMax) leftMax = height[l];
                else water += leftMax - height[l];
                l++;
            } else {                                 // right is the lower end
                if (height[r] >= rightMax) rightMax = height[r];
                else water += rightMax - height[r];
                r--;
            }
        }
        return water;
    }
}
```

## 7. Quick Revision
Water above a bar = min(tallest to its left, tallest to its right) - its height. Two pointers: always process the **lower** end; its own running max is its water level, because the other end has a wall at least as tall.
Skeleton: `while (l < r) { if (h[l] <= h[r]) { h[l] >= lm ? lm = h[l] : water += lm - h[l]; l++; } else { mirror with rm; r--; } }`

## 8. Pattern
- Primary: Two Pointers (opposite ends, process the lower side)
- Secondary: Prefix/Suffix maximum arrays (DP-style precompute), Monotonic Stack (alternative)
