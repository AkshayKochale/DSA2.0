# <span style="color:orange">  Valid Parentheses </span>

## 1. Problem Statement
LeetCode 20 / NeetCode "Validate Parentheses". Given a string `s` containing only `'('`, `')'`, `'{'`, `'}'`, `'['`, `']'`, return `true` if it is valid: every open bracket is closed by the same type of bracket, in the correct order, and every close bracket has a matching open bracket.
Constraints: `1 <= s.length <= 1000`. Recommended: O(n) time, O(n) space.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public boolean isValid(String s) {

        int n = s.length();
        if(n%2!=0)return false;
        Stack<Character> st= new Stack();

           for(int i=0;i<n;i++) {
            char c= s.charAt(i);
            if(c=='[' || c=='{' || c=='(')st.add(c);
            else{
                if(st.isEmpty())return false;
                char prev = st.pop();
                if(c!=getRev(prev))return false;
            }
           }

        return st.isEmpty();
        
    }

    static char getRev(char c){

           if(c=='[') return ']';
           if(c=='{') return '}';
           if (c=='(') return ')';

           return '-';
    }
}
```

Return `false` immediately for odd length. Push every opening bracket. On a closing bracket, the stack must be non-empty and the popped opener's matching closer (`getRev`) must equal it. At the end the stack must be empty.

## 3. Complexity
- Time: O(n)
- Space: O(n) (worst case all opening brackets)
- Correct and optimal. Hand-checked on `"[]"`, `"([{}])"`, `"[(])"`, `"("`, `"))"`.

## 4. What I Missed
No correctness problems. Remaining improvements:
- `Stack` is a legacy synchronized class (extends `Vector`) and `new Stack()` is a raw type (unchecked warning). Prefer `Deque<Character> stack = new ArrayDeque<>()` with `push`/`pop`.
- `st.add(c)` works but `push` states the intent.
- Push the **expected closing bracket** instead of the opener: then the closing branch is just `stack.isEmpty() || stack.pop() != c`, and the `getRev` helper (with its dummy `'-'` return) disappears.
- Did not state why a **stack** is needed instead of counters: `"[(])"` has balanced counts of every type but is invalid, because order matters.
- The `else` branch treats any non-opening character as a closer. That is safe only because the constraint limits input to the six bracket characters.
- Good, keep: the `n % 2 != 0` early exit is a valid shortcut; both failure conditions (empty stack on a closer, leftover openers at the end) are handled.

## 5. Optimal Approach
Scan left to right. The most recent unmatched opener must be the next one to close, which is last-in-first-out, so use a stack. For each opener push the closer it expects. For each closer, the stack must be non-empty and its top must equal that closer; otherwise return `false`. At the end, the stack must be empty (no unclosed openers).

## 6. Optimal Java Code

```java
class Solution {
    public boolean isValid(String s) {
        if (s.length() % 2 != 0) return false;

        Deque<Character> stack = new ArrayDeque<>();
        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);
            if (c == '(') stack.push(')');
            else if (c == '[') stack.push(']');
            else if (c == '{') stack.push('}');
            else if (stack.isEmpty() || stack.pop() != c) return false;
        }
        return stack.isEmpty();
    }
}
```

## 7. Quick Revision
The latest unmatched opener must close first (LIFO), so use a stack: push the expected closer for each opener; on a closer, the stack must be non-empty and its top must equal it; at the end the stack must be empty.
Counters are not enough because order matters (`"[(])"` has balanced counts but is invalid).

## 8. Pattern
- Primary: Stack (LIFO matching of nested structure)
- Secondary: Single-pass string scan, Early exit on odd length

# <span style="color:orange">  Min Stack </span>

## 1. Problem Statement
LeetCode 155 / NeetCode "Minimum Stack". Design a stack supporting `push(val)`, `pop()`, `top()` and `getMin()` (the minimum element currently in the stack). **Each operation must run in O(1) time.**
Constraints: `-2^31 <= val <= 2^31 - 1`; `pop`, `top`, `getMin` are always called on a non-empty stack; at most 3 x 10^4 calls. Recommended: O(1) per call, O(n) space.

## 2. My Approach
Two submissions (both unmodified).

**Attempt 1: list, scan for the minimum**

```java
class MinStack {

    List<Integer> l=null;

    public MinStack() {
        l= new ArrayList<>();
    }
    
    public void push(int val) {
        l.add(val);
    }
    
    public void pop() {
        l.remove(l.size()-1);
    }
    
    public int top() {
        return l.get(l.size()-1);
    }
    
    public int getMin() {
        int min = Integer.MAX_VALUE;

        for(  int i : l)min=Math.min(min,i);
        return min;        
    }
}
```

An `ArrayList` used as a stack. `getMin` scans the whole list.

**Attempt 2: list + min-heap + index map**

```java
class MinStack {

    List<Integer> l=null;
    Map<Integer,Pair> map=null;
    PriorityQueue<Pair> q= null;

    int i=0;

    public MinStack() {
        l= new ArrayList<>();
        map= new HashMap<>();
        q = new PriorityQueue<Pair>((a,b)->Long.compare(a.v, b.v));
    }
    
    public void push(int val) {
        l.add(val);
        Pair p =new Pair(i,val);
        map.put(i,p);
        q.add(p);
        i++;
    }
    
    public void pop() {
        l.remove(l.size()-1);
        i--;
        Pair  p= map.get(i);
        q.remove(p);
        map.remove(i);

    }
    
    public int top() {
        return l.get(l.size()-1);
    }
    
    public int getMin() {
        return (int)q.peek().v;        
    }

    class Pair{

        int i;
        long v;

        public Pair(int i, long v){
               this.i= i;
               this.v=v; 
        }

        public String toString(){
            return i+" : "+ v;
        }
    }
}
```

Every pushed value also goes into a min-heap (as a `Pair` object) and into a map from stack position to that `Pair`. `pop` looks up the popped position's `Pair` in the map and removes it from the heap. `getMin` peeks the heap.

## 3. Complexity
- Attempt 1: push O(1), pop O(1), top O(1), **getMin O(n)**. Space O(n). Correct, but violates the O(1) requirement.
- Attempt 2: push O(log n), **pop O(n)** (`PriorityQueue.remove(Object)` is a linear scan), top O(1), getMin O(1). Space O(n) across three structures. Correct, but violates the O(1) requirement.
- Optimal: all operations O(1), space O(n).

## 4. What I Missed
- **Key observation:** the stack only changes at the top, so the minimum of "everything from the bottom up to this element" is fixed the moment the element is pushed and never changes while it stays. Store that running minimum **with each element**. `pop` then restores the previous minimum for free, because it was stored with the element underneath.
- Reached for a heap because the word "min" appeared. A heap is a general structure that supports deleting arbitrary elements; here deletions are always the most recent push (LIFO), so that generality is unnecessary, and in Java removing a specific object from a `PriorityQueue` costs O(n).
- A single `min` variable fails: after `push 5, 3, 1` then `pop`, the minimum must become 3, which the variable no longer knows.
- Attempt 2 clutter: counter `i` always equals `l.size()`; `Pair.i` is never used; `long v` is unnecessary for `int` values; the map exists only to find the `Pair` to remove from the heap.
- Attempt 1: nothing wrong except the O(n) `getMin`; also `List<Integer> l = null;` then assigning in the constructor is unnecessary (initialize at declaration).
- Space-saving encodings (storing differences from the minimum in one stack) exist, but need `long` arithmetic to handle `-2^31`/`2^31 - 1` and are error-prone; not worth it here.

## 5. Optimal Approach
Keep a single stack where every entry stores two numbers: the value and the minimum of all values at or below it. On `push(val)`, the new minimum is `min(val, previous entry's minimum)` (or `val` if the stack is empty). `pop` just removes the top entry. `top` returns the top entry's value, `getMin` returns its stored minimum. (Equivalent: a second stack holding prefix minima.) All O(1), O(n) space.

## 6. Optimal Java Code

```java
class MinStack {
    private final Deque<int[]> stack = new ArrayDeque<>();   // each entry: {value, minSoFar}

    public MinStack() {}

    public void push(int val) {
        int min = stack.isEmpty() ? val : Math.min(val, stack.peek()[1]);
        stack.push(new int[]{val, min});
    }

    public void pop() {
        stack.pop();
    }

    public int top() {
        return stack.peek()[0];
    }

    public int getMin() {
        return stack.peek()[1];
    }
}
```

## 7. Quick Revision
The stack only changes at the top, so store with every element the minimum of everything beneath it (including itself): `push` computes `min(val, previous top's min)`; `pop` restores the old minimum for free. All O(1).
Heaps are overkill because deletions are always LIFO; a lone `min` variable fails because it cannot recover the previous minimum after a pop.

## 8. Pattern
- Primary: Stack with augmented state (prefix minimum stored per element)
- Secondary: Data structure design, Two-stack variant (values stack + minimums stack), Heap (rejected: arbitrary delete is O(n) in Java)

# <span style="color:orange">  Evaluate Reverse Polish Notation </span>

## 1. Problem Statement
LeetCode 150 / NeetCode "Evaluate Reverse Polish Notation". Given a valid expression in Reverse Polish Notation as a `String[] tokens`, return its integer value. Operators are `+`, `-`, `*`, `/`; operands may be integers or results of other operations; integer division truncates toward zero.
Example: `["1","2","+","3","*","4","-"]` -> `5` (that is `((1 + 2) * 3) - 4`).
Constraints: `1 <= tokens.length <= 10,000`; each token is an operator or an integer in `[-200, 200]`. Recommended: O(n) time, O(n) space.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public int evalRPN(String[] tokens) {

        
        Stack<Integer> st= new Stack<>();

        for(int i=0;i<tokens.length;i++){
            String s= tokens[i];    
            int num =isNumber(s);
            if(num==-1000)
                 num=performOps(st,s);
              
              st.add(num); 
        }

        return st.pop();
    }

    public int isNumber(String s){
        try {
             return Integer.parseInt(s);
        }catch(Exception e){}

        return -1000;
    }

    public int performOps(Stack<Integer> st, String ops){

           int i = st.pop();
           int j = st.pop();

           if(ops.equals("+")) return i+j;
           if(ops.equals("-")) return j-i;
           if(ops.equals("*")) return i*j;
           if(ops.equals("/")) return j/i;
          
          return -1000;
    }
}
```

Scan the tokens with a stack. Try to parse each token as an integer; if parsing fails, treat it as an operator: pop two operands (the first pop is the right operand), compute, and push the result. Return the last value on the stack.

## 3. Complexity
- Time: O(n) (but every operator token throws and catches an exception, which is slow in practice)
- Space: O(n)
- Correct. Hand-checked on `["1","2","+","3","*","4","-"]` -> 5 and `["4","13","5","/","+"]` -> 6; operand order for `-` and `/` is right.

## 4. What I Missed
- **Exceptions used as control flow:** `Integer.parseInt` throws `NumberFormatException` for every `+ - * /` token (roughly half the tokens in a typical input). Creating exceptions is slow; check for an operator directly instead.
- **Magic sentinel:** `-1000` means "not a number" and is also the fallback return of `performOps`. It is safe only because numbers are limited to `[-200, 200]`; any token that parsed to `-1000` would be misread as an operator.
- Legacy `Stack` class (extends `Vector`, synchronized); prefer `Deque<Integer> stack = new ArrayDeque<>()` with `push`/`pop`.
- Did not state why a stack works: an operator applies to the two **most recent unconsumed values**, and its result becomes a new unconsumed value (LIFO).
- Did not state the operand order rule out loud: the first value popped is the **right** operand (`left - right`, `left / right`).
- Java's `int` division already truncates toward zero, so no extra handling is needed (unlike Python).
- Names (`isNumber` returns an `int`, `i`/`j` for operands) are misleading; `b`/`a` or `right`/`left` read better.
- Good, keep: correct operand order for `-` and `/`, and a single stack pass.

## 5. Optimal Approach
Scan tokens left to right. A number goes onto the stack. An operator pops the right operand then the left operand, applies the operation, and pushes the result back. After the last token, the single remaining value is the answer. Test for the four operators with a `switch` and parse everything else as a number, so no exceptions are involved. O(n) time, O(n) space.

## 6. Optimal Java Code

```java
class Solution {
    public int evalRPN(String[] tokens) {
        Deque<Integer> stack = new ArrayDeque<>();
        for (String token : tokens) {
            switch (token) {
                case "+":
                    stack.push(stack.pop() + stack.pop());
                    break;
                case "-": {
                    int right = stack.pop(), left = stack.pop();
                    stack.push(left - right);
                    break;
                }
                case "*":
                    stack.push(stack.pop() * stack.pop());
                    break;
                case "/": {
                    int right = stack.pop(), left = stack.pop();
                    stack.push(left / right);
                    break;
                }
                default:
                    stack.push(Integer.parseInt(token));
            }
        }
        return stack.pop();
    }
}
```

## 7. Quick Revision
In postfix, an operator applies to the two most recent unconsumed values, so use a stack: numbers are pushed; an operator pops right then left, computes `left op right`, and pushes the result.
Check for operators first (a `switch`), never use parse exceptions or sentinel values to detect them.

## 8. Pattern
- Primary: Stack (LIFO evaluation of postfix expressions)
- Secondary: Expression parsing, Simulation

# <span style="color:orange">  Daily Temperatures </span>

## 1. Problem Statement
LeetCode 739 / NeetCode "Daily Temperatures". Given an integer array `temperatures`, return an array `result` where `result[i]` is the number of days after day `i` until a **strictly warmer** temperature appears; if there is none, `result[i] = 0`.
Example: `[30,38,30,36,35,40,28]` -> `[1,4,1,2,1,0,0]`.
Constraints: `1 <= temperatures.length <= 100,000`, `1 <= temperatures[i] <= 100`. Recommended: O(n) time, O(n) space.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public int[] dailyTemperatures(int[] arr) {
        
        int n= arr.length;
        int ans[] = new int[n];
        Stack<Integer> st =new Stack<>();

        for(int i=0;i<n;i++){

                while(!st.isEmpty() && arr[st.peek()]<arr[i]){
                int l = st.pop();
                ans[l]=i-l;
                }   
            st.add(i); 
        }
        return ans;
    }
}
```

Scan left to right with a stack of indices whose temperatures are non-increasing (days still waiting for a warmer day). For each day `i`, pop every index with a strictly lower temperature, set its answer to `i - index`, then push `i`. Indices never popped keep the default `0`.

## 3. Complexity
- Time: O(n) amortized (each index is pushed once and popped at most once)
- Space: O(n) (stack, plus the output array)
- Correct. Hand-traced on Example 1 -> `[1,4,1,2,1,0,0]` and Example 2 `[22,21,20]` -> `[0,0,0]`.

## 4. What I Missed
No correctness problems. Remaining gaps:
- **Did not state why the nested `while` is still O(n):** every index enters the stack once and leaves at most once, so total pops <= n. A `while` inside a `for` looks like O(n^2) unless you say this.
- **Did not state the invariant:** the stack always holds the indices of days that are still waiting for a warmer day, with temperatures non-increasing from bottom to top. That is why popping from the top while `<` is enough: once the top is >= today, everything beneath it is even warmer.
- Strictness: the condition is `<` (not `<=`) because the answer needs a *strictly* warmer day; equal temperatures stay on the stack.
- Alternative using the constraint `temperatures[i] <= 100`: sweep right to left keeping the latest index of each temperature (array of size 101) and, for each day, check temperatures `t+1..100` (O(100 n) time, O(100) extra space). Valid, but the monotonic stack is simpler and faster in general.
- Legacy `Stack` (extends `Vector`, synchronized): prefer `Deque<Integer> stack = new ArrayDeque<>()` with `push`/`pop`/`peek`. `st.add(i)` works but `push` states the intent.
- Names: the variable `l` looks like the digit `1` (use `prev`), and `arr` is better named `temperatures`.
- Good, keep: storing indices (not values) because the answer is a distance, and letting unresolved days stay `0` by default.

## 5. Optimal Approach
Monotonic (non-increasing) stack of indices. Instead of asking "for each day, where is the next warmer day?", stand on the current day and ask "which earlier days were waiting for something warmer than themselves?" Those are on top of the stack. Pop each one that is strictly colder than today and record `i - index`. Push today. Each index is pushed and popped at most once, so O(n) time and O(n) space.

## 6. Optimal Java Code

```java
class Solution {
    public int[] dailyTemperatures(int[] temperatures) {
        int n = temperatures.length;
        int[] result = new int[n];
        Deque<Integer> stack = new ArrayDeque<>();   // indices of days still waiting for a warmer day

        for (int i = 0; i < n; i++) {
            while (!stack.isEmpty() && temperatures[stack.peek()] < temperatures[i]) {
                int prev = stack.pop();
                result[prev] = i - prev;
            }
            stack.push(i);
        }
        return result;
    }
}
```

## 7. Quick Revision
The stack holds days still waiting for a warmer day (temperatures non-increasing bottom to top). Today pops every strictly colder day from the top, answers them with `i - index`, then pushes itself.
Each index is pushed and popped once, so O(n). Clue: "distance to the next greater element" means monotonic stack.

## 8. Pattern
- Primary: Monotonic Stack (next greater element)
- Secondary: Stack of indices, Amortized analysis, Bounded-value array trick (values <= 100)

# <span style="color:orange">  Car Fleet </span>

## 1. Problem Statement
LeetCode 853 / NeetCode "Car Fleet". `n` cars drive on a one-lane road to a destination at `target` miles. Car `i` starts at `position[i]` with speed `speed[i]`. A car cannot pass the car ahead; it can only catch up and then drive at the same speed as the car ahead. A fleet is a set of cars driving together; a single car is a fleet. A car that catches a fleet exactly at the destination joins that fleet. Return the number of fleets that arrive at the destination.
Example: `target = 10, position = [4,1,0,7], speed = [2,2,1,1]` -> `3`.
Constraints: `1 <= n <= 100,000`, `0 < target <= 1,000,000`, `1 <= speed[i] <= 1,000,000`, `0 <= position[i] < target`, positions unique. Recommended: O(n log n) time, O(n) space.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public int carFleet(int target, int[] position, int[] speed) {

        int n= position.length;
        Pair arr[]=new Pair[n];
        Stack<Pair> st =new Stack<>();

        for(int i=0;i<n;i++){
            double time = (double)(target - position[i]) / speed[i];

            arr[i]=new Pair(position[i],speed[i],time);
        }

        Arrays.sort(arr,(a,b)->b.p-a.p);
        
        for(int i=0;i<n;i++){
            
            Pair cur= arr[i];
            if(st.isEmpty()) st.add(cur);
            else{
                Pair prev= st.peek();
                if(cur.t>prev.t)st.add(cur);
            }
             
        }

        return st.size();
    }

    class Pair{
        int p;
        int s;
         double t;

        public Pair(int p, int s,double t){
            this.p=p; this.s=s;this.t=t;
        }
    }
}
```

Compute each car's time to reach the target, sort cars by position descending (closest to the target first), then scan: a car starts a new fleet (push) only if its time is strictly greater than the time of the fleet ahead (top of the stack); otherwise it catches up and merges. The answer is the stack size.

## 3. Complexity
- Time: O(n log n) (sorting dominates; the scan is O(n))
- Space: O(n)
- Correct. Hand-traced on Example 1 (`[1,4]`, speeds `[3,2]`, target 10 -> 1) and Example 2 (-> 3).

## 4. What I Missed
- **The stack is never popped; only its top is read.** The stack holds strictly increasing times, so the top is just the largest time seen so far. Replace the stack with one variable (`slowest`) and a counter. The problem reduces to **counting how many times a new strict maximum appears** in the times, scanning from the front car to the back car.
- Did not state why each car's effective arrival time is `max(own time, time of the fleet ahead)`: a car can never pass, so it can only arrive no earlier than the fleet in front.
- Ties: equal times mean the car catches the fleet exactly at the destination and **joins** it, hence the strict `>` for a new fleet. Correct in the code, but worth stating.
- Floating point: comparing `double` times works here because the numerator and denominator are exactly representable integers, and IEEE division is correctly rounded (equal fractions give equal doubles, and distinct fractions in this range differ by far more than the rounding error). An integer-only comparison avoids the question: `(target - p1) * s2 > (target - p2) * s1` with `long` (products up to 10^12).
- `Pair.s` is never used; `Pair` should be a `static` nested class (or use `int[][]`); `Stack` is a legacy class; `b.p - a.p` is a subtraction comparator (safe here since positions are < 10^6, but use `Integer.compare`).
- Constraint-based alternative: positions are unique and < `target <= 10^6`, so an array indexed by position could replace the sort (O(n + target)); not practically better than sorting 10^5 items, so not worth it.
- Good, keep: sorting by position descending and processing the front car first; the strict `>` for ties.

## 5. Optimal Approach
Cars cannot pass, so the front car dictates the pace of everyone behind it. Reduce each car to one number: its time to reach the target, `(target - position) / speed`. Process cars from the one closest to the target to the farthest. If a car's time is **greater** than the slowest time of everything ahead, it can never catch up: it starts a new fleet. If its time is **less than or equal**, it catches up (or arrives together) and merges into the fleet ahead, adopting that fleet's time. So the answer is the number of strict running maximums in the time sequence. O(n log n) for the sort, O(1) extra for the scan.

## 6. Optimal Java Code

```java
class Solution {
    public int carFleet(int target, int[] position, int[] speed) {
        int n = position.length;
        int[][] cars = new int[n][2];
        for (int i = 0; i < n; i++) {
            cars[i][0] = position[i];
            cars[i][1] = speed[i];
        }
        Arrays.sort(cars, (a, b) -> Integer.compare(b[0], a[0]));   // closest to target first

        int fleets = 0;
        double slowest = 0;                                          // arrival time of the fleet ahead
        for (int[] car : cars) {
            double time = (double) (target - car[0]) / car[1];
            if (time > slowest) {          // cannot catch the fleet ahead -> new fleet
                fleets++;
                slowest = time;
            }
        }
        return fleets;
    }
}
```

## 7. Quick Revision
Convert each car to its arrival time `(target - pos) / speed`, sort by position descending, and count how many times a time is strictly larger than every time ahead: each such car cannot catch the fleet in front, so it starts a new fleet.
No stack needed (it never pops); equal times merge.

## 8. Pattern
- Primary: Sorting + Greedy scan (count strict running maximums)
- Secondary: Monotonic Stack (used by the standard solution, but only the top is read), Reducing two attributes to one (time to destination)

# <span style="color:orange">  Largest Rectangle in Histogram </span>

## 1. Problem Statement
LeetCode 84 / NeetCode "Largest Rectangle In Histogram". Given an integer array `heights` where `heights[i]` is the height of a bar of width 1, return the area of the largest rectangle that can be formed among the bars.
Examples: `[7,1,7,2,2,4]` -> `8`; `[1,3,7]` -> `7`.
Constraints: `1 <= heights.length <= 100,000`, `0 <= heights[i] <= 10,000`. Recommended: O(n) time, O(n) space.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public int largestRectangleArea(int[] nums) {
        
        int ans =Integer.MIN_VALUE;
        int n = nums.length;
        int it =1;

        while(true){

            int s =0;
            int maxW =0;
            int curW=0; boolean wf=false;   

            while(s<n){
                if(nums[s]==0){
                    maxW=Math.max(maxW,curW);
                    curW =0;
                }
                else {
                    curW++;
                    nums[s]--;
                    wf = true;
                }
                s++;
            }
            
            maxW = Math.max(maxW,curW);
            ans = Math.max(ans, maxW * it);
            if(!wf)break;
            it++;

        }


        return ans;
    }
}
```

Peel the histogram layer by layer. In pass `it`, every bar that still has height left is part of level `it`: decrement it and count the longest run of consecutive such bars (`maxW`). The best rectangle of height `it` has area `maxW * it`. Repeat until no bar has height left.

## 3. Complexity
- Time: O(n * H) where H = max height. Each pass is O(n) and there are H + 1 passes. With `n = 10^5` and `H = 10^4` that is up to about 10^9 steps (not run by me; expect a timeout risk).
- Space: O(1) extra, but it **mutates the input array** (`nums[s]--`).
- Correct. Hand-traced on `[7,1,7,2,2,4]` -> 8 and `[1,3,7]` -> 7. Cost depends on the value range, not on n.

## 4. What I Missed
- **The cost depends on the heights, not on n.** The outer loop runs once per height level (up to 10,000), so the time is O(n * H). This is the same flaw as scanning the value range in Longest Consecutive Sequence: loop over the elements, not over the value domain. Estimating the work before coding (`10^5 * 10^4 = 10^9`) would have flagged it.
- **Key observation missed:** a rectangle's height equals the height of its shortest bar. So enumerate the **limiting bar** (n candidates), not the height levels. For bar `i` with height `h`, the rectangle extends left and right until a strictly shorter bar: area = `h * (rightSmaller - leftSmaller - 1)`.
- Finding the previous-smaller and next-smaller bar for every index is the same "next greater/smaller element" pattern as Daily Temperatures: a **monotonic stack**.
- The code destroys the caller's input (`nums[s]--`); a function like this should not mutate its argument.
- Even enumerating only the distinct heights present would still be O(n * distinct) and not O(n).
- Minor: `ans = Integer.MIN_VALUE` could be `0` (areas are never negative); names `it`, `wf`, `curW`, `maxW` are cryptic.
- Good, keep: the idea is sound (rectangle of height `h` = longest run of bars with height >= `h`, times `h`); it handles zeros and the all-zero input (returns 0).

## 5. Optimal Approach
Treat every bar as the shortest bar of its rectangle. Its rectangle spans from just after the previous strictly shorter bar to just before the next strictly shorter bar. Use a monotonic stack of indices with strictly increasing heights. When bar `i` is not taller than the top, pop the top: its right boundary is `i`, its left boundary is the new top of the stack (or `-1` if empty), so width = `i - left - 1`. Add a sentinel height 0 at the end to flush the stack. Each index is pushed and popped once: O(n) time, O(n) space.

## 6. Optimal Java Code

```java
class Solution {
    public int largestRectangleArea(int[] heights) {
        int n = heights.length;
        Deque<Integer> stack = new ArrayDeque<>();   // indices, heights strictly increasing bottom to top
        int best = 0;

        for (int i = 0; i <= n; i++) {
            int curr = (i == n) ? 0 : heights[i];     // sentinel 0 flushes the stack at the end
            while (!stack.isEmpty() && heights[stack.peek()] >= curr) {
                int h = heights[stack.pop()];
                int left = stack.isEmpty() ? -1 : stack.peek();   // previous strictly smaller bar
                best = Math.max(best, h * (i - left - 1));
            }
            stack.push(i);
        }
        return best;
    }
}
```

## 7. Quick Revision
The best rectangle's height is its shortest bar, so for each bar find the previous and next strictly smaller bar: area = `h * (right - left - 1)`.
Keep a stack of indices with increasing heights; when bar `i` is not taller than the top, pop it (right boundary `i`, left boundary the new top or -1); add a sentinel 0 at the end to flush. O(n).
- Also remember how to find out next and prev smaller element for any element using stack.

## 8. Pattern
- Primary: Monotonic Stack (previous / next smaller element)
- Secondary: Enumerate the limiting element, Sentinel technique, Prefix arrays of smaller-boundaries (two-pass alternative)
