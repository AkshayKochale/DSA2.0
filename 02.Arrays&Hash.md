 #  <span style="color:orange"> Contains Duplicate</span>

## 1. Problem Statement
LeetCode 217 / NeetCode "Duplicate Integer". Given an integer array `nums`, return `true` if any value appears more than once, otherwise `false`.
Constraints: `0 <= nums.length <= 10^5`, `-10^9 <= nums[i] <= 10^9`.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public boolean hasDuplicate(int[] nums) {
        
        Set<Integer> set=new HashSet<>();

        for(int i:nums){

            if(set.contains(i))return true;
            set.add(i);
        }

        return false;
    }
}
```

Scan left to right, keep a `HashSet` of seen values. If the current value is already in the set, return `true`. Otherwise add it.

## 3. Complexity
- Time: O(n) average
- Space: O(n) worst case (no duplicates)

## 4. What I Missed
- Nothing wrong with correctness or complexity. This already matches the optimal time/space target.
- `contains` + `add` does two hash lookups per element. `add` returns `false` if the value was present, so one call is enough.
- No pre-sizing of the `HashSet`, so it may rehash several times for n up to 10^5.
- Did not weigh the alternative trade-off: sort first, then compare neighbors (O(n log n) time, O(1) extra space if in-place sorting is allowed).
- Pigeonhole shortcut does not apply here: value range (~2*10^9) is far larger than n, so no early "must have duplicate" exit and no boolean-array approach.

## 5. Optimal Approach
Hash set with early exit, using the return value of `add`. If memory must be O(1), sort in place and check adjacent elements (slower, mutates input).

## 6. Optimal Java Code

```java
class Solution {
    public boolean hasDuplicate(int[] nums) {
        Set<Integer> seen = new HashSet<>(nums.length * 2);
        for (int num : nums) {
            if (!seen.add(num)) return true;
        }
        return false;
    }
}
```

Sorting alternative (O(1) extra space, mutates input):

```java
class Solution {
    public boolean hasDuplicate(int[] nums) {
        Arrays.sort(nums);
        for (int i = 1; i < nums.length; i++) {
            if (nums[i] == nums[i - 1]) return true;
        }
        return false;
    }
}
```

## 7. Quick Revision
"Have I seen this value before?" is a membership question, so use a hash set and return the moment `add` fails.
Duplicates become adjacent after sorting, which trades time for space.

## 8. Pattern
- Primary: Hash Set (seen-before / membership check)
- Secondary: Sorting + adjacent comparison

# <span style="color:orange">  Valid Anagram </span>

## 1. Problem Statement
LeetCode 242 / NeetCode "Valid Anagram". Given strings `s` and `t`, return `true` if they are anagrams (same characters, same counts, any order), otherwise `false`.
Constraints: `1 <= s.length, t.length <= 5 * 10^4`, both consist of lowercase English letters.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public boolean isAnagram(String s, String t) {
    
       int arr[]= new int[26]; 

        for(int i=0;i<s.length();i++){

            char cur= s.charAt(i);
            arr[cur -'a']++;
        }

        for(int i=0;i<t.length();i++){

            char c= t.charAt(i);
            arr[c - 'a']--;
        }

        for(int i: arr)
            if(i!=0)
                return false;


        return true;
    }
}
```

Use one 26-slot frequency array. Increment for each char of `s`, decrement for each char of `t`, then check every slot is zero.

## 3. Complexity
- Time: O(n + m + 26) = O(n + m)
- Space: O(1) (fixed 26-int array)

## 4. What I Missed
- No early exit when `s.length() != t.length()`. Different lengths can never be anagrams, so this is a free O(1) check.
- Correctness silently depends on the "lowercase only" constraint. Uppercase, digits or Unicode would throw `ArrayIndexOutOfBoundsException` or give wrong results. Did not state this assumption.
- Did not consider the follow-up: Unicode input needs a `HashMap<Character, Integer>` (or a larger array).
- Can fail faster: during the decrement pass, a count going below zero already proves a mismatch (once lengths are equal).
- Did not mention the sorting alternative (O(n log n)) and why counting beats it.

## 5. Optimal Approach
Check lengths first. With equal lengths, one counting array is enough: increment for `s`, decrement for `t`, and return `false` the moment any count goes negative. Since total increments equal total decrements, no negative count means all counts are zero, so no final scan is needed.

## 6. Optimal Java Code

```java
class Solution {
    public boolean isAnagram(String s, String t) {
        if (s.length() != t.length()) return false;

        int[] count = new int[26];
        for (int i = 0; i < s.length(); i++) {
            count[s.charAt(i) - 'a']++;
            count[t.charAt(i) - 'a']--;
        }
        for (int c : count) {
            if (c != 0) return false;
        }
        return true;
    }
}
```

Unicode follow-up: replace the array with `Map<Character, Integer>` (same logic, O(k) space for k distinct characters).

## 7. Quick Revision
Anagram means same character frequencies, so order is irrelevant: count instead of sort. Lowercase letters mean a fixed 26-slot array (O(1) space), and unequal lengths mean instant `false`.

## 8. Pattern
- Primary: Frequency counting (hash table / counting array)
- Secondary: Sorting (alternative), fixed-alphabet array as a hash map

# <span style="color:orange">  Two Sum </span>

## 1. Problem Statement
LeetCode 1 / NeetCode "Two Integer Sum". Given an integer array `nums` and an integer `target`, return indices `i` and `j` such that `nums[i] + nums[j] == target` and `i != j`. Exactly one valid pair exists. Return the smaller index first.
Constraints: `2 <= nums.length <= 1000`, `-10^7 <= nums[i], target <= 10^7`.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        
        int arr[] = new int[2];

        //<number,idx>
        HashMap<Integer,Integer> map= new HashMap<>();

        for(int i=0;i<nums.length;i++){
             int cur = target-nums[i];
            if(map.containsKey(cur)){
                arr[0]=map.get(cur);
                arr[1]=i;
                return arr;
            }
            map.put(nums[i],i);
        }

        return arr;
    }
}
```

One pass. For each `nums[i]`, look up its complement `target - nums[i]` in a map of previously seen values (value -> index). If found, return `[storedIndex, i]`. Otherwise store the current value and index.

## 3. Complexity
- Time: O(n) average
- Space: O(n)

## 4. What I Missed
- `containsKey` followed by `get` is two lookups. One `get` plus a null check is enough.
- The fallback `return arr` returns `[0, 0]`, which looks like a valid answer. An unreachable fallback should be explicit (`new int[0]` or throw).
- `arr` is allocated before it is needed. Create the result only when a pair is found.
- Did not state why check-then-insert is correct: the lookup before the `put` guarantees `i != j` and handles duplicates like `[5, 5]`.
- Did not mention the brute force (O(n^2)) and sort + two pointers (loses original indices) alternatives.
- No overflow discussion: `target - nums[i]` is safe here (values up to 10^7), but would need `long` for full int range.

## 5. Optimal Approach
Rearrange `a + b = target` into `b = target - a`. Fix one element, and the other is fully determined, so the question becomes "have I seen this exact value before?". A hash map from value to index answers that in O(1). Look up first, then insert, in a single pass.

## 6. Optimal Java Code

```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>(nums.length * 2);
        for (int i = 0; i < nums.length; i++) {
            Integer j = seen.get(target - nums[i]);
            if (j != null) return new int[]{j, i};
            seen.put(nums[i], i);
        }
        return new int[0]; // unreachable: a valid pair is guaranteed
    }
}
```

## 7. Quick Revision
Fixing one number fixes the other (`target - x`), so ask "have I seen the complement?" with a value -> index map. Look up before inserting, which avoids reusing the same element and handles duplicates.

## 8. Pattern
- Primary: Hash Map (complement lookup)
- Secondary: One-pass "seen so far" scan, Sort + Two Pointers (when indices are not needed)

# <span style="color:orange">  Group Anagrams </span>

## 1. Problem Statement
LeetCode 49 / NeetCode "Anagram Groups". Given an array of strings `strs`, group all anagrams together into sublists. Output order does not matter.
Constraints: `1 <= strs.length <= 10000`, `0 <= strs[i].length <= 100`, lowercase English letters only.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public List<List<String>> groupAnagrams(String[] strs) {
        
        HashMap<HashMap<Character,Integer>,List<String>> map=new HashMap<>();

        for(String s:strs){
            HashMap<Character,Integer> tm = buildFreqMap(s);

            List<String> tl= map.getOrDefault(tm,new ArrayList<>());
            tl.add(s);
            map.put(tm,tl);
        }

        List<List<String>> ans= new ArrayList<>();

        for(Map.Entry<HashMap<Character,Integer>,List<String>> entry : map.entrySet()){
            ans.add(entry.getValue());
        }

        return ans;
    }

    static HashMap<Character,Integer> buildFreqMap(String s){
         HashMap<Character,Integer> map= new HashMap<Character,Integer>();

           for( int i=0;i<s.length();i++){
                map.put(s.charAt(i),map.getOrDefault(s.charAt(i),0)+1);
           }

         return map;
    }
}
```

For each string, build a `HashMap<Character,Integer>` of character frequencies and use that map itself as the key of an outer map to a list of strings. Anagrams produce equal frequency maps, so they land in the same list. Return all the lists.

## 3. Complexity
- Time: O(m * n) average (m strings, n max length), but with heavy constants (boxing, entry objects, map hashing/equality per lookup)
- Space: O(m * k) for the frequency-map keys (k = distinct chars, at most 26), plus the output

## 4. What I Missed
- Correct but heavy: a `HashMap` per string means boxed `Character`/`Integer` objects and `Node` entries. The constraint (lowercase only) allows a fixed 26-slot `int[]`, which you used in Valid Anagram.
- Weak key hash: `HashMap.hashCode()` is the sum of `(keyHash ^ valueHash)`. Example: "aa" (97^2) and "b" (98^1) both hash to 99. `equals` still separates them, so results are correct, but collisions cost extra comparisons.
- `getOrDefault(tm, new ArrayList<>())` allocates a new list on every iteration, even when the key exists. `computeIfAbsent` allocates only when needed, and the extra `put` is redundant once the list is stored.
- The last loop is just `new ArrayList<>(map.values())`.
- Did not mention the simpler sorted-string key (`"tops"` -> `"opst"`), or the Java gotcha that `int[]` cannot be a map key directly (identity hash), and the fix.

## 5. Optimal Approach
Two strings are anagrams iff they have the same signature. Compute a cheap, canonical signature per string and group by it with `computeIfAbsent`. Best signature for lowercase letters: a `char[26]` count array converted with `new String(count)`. Counts are at most 100, so each fits in a `char`, and the fixed length of 26 makes the key unambiguous (no delimiter needed). Alternative: sort the characters of each string (O(n log n) per string; with n <= 100 this is also practical).

## 6. Optimal Java Code

```java
class Solution {
    public List<List<String>> groupAnagrams(String[] strs) {
        Map<String, List<String>> groups = new HashMap<>();
        for (String s : strs) {
            char[] count = new char[26];
            for (int i = 0; i < s.length(); i++) {
                count[s.charAt(i) - 'a']++;
            }
            groups.computeIfAbsent(new String(count), k -> new ArrayList<>()).add(s);
        }
        return new ArrayList<>(groups.values());
    }
}
```

Sorting alternative for the key:

```java
char[] chars = s.toCharArray();
Arrays.sort(chars);
String key = new String(chars);
```

## 7. Quick Revision
Grouping means "map each item to a canonical signature, then bucket by signature". For anagrams the signature is the 26-count array (as a `String`) or the sorted string. `int[]` has identity hashing, so convert it before using it as a key.

## 8. Pattern
- Primary: Hash Map grouping by canonical key
- Secondary: Frequency counting (fixed 26-slot array), Sorting as signature

# <span style="color:orange">  Top K Frequent Elements </span>

## 1. Problem Statement
LeetCode 347 / NeetCode "Top K Elements in List". Given an integer array `nums` and an integer `k`, return the `k` most frequent elements. The answer is guaranteed unique and may be returned in any order.
Constraints: `1 <= nums.length <= 10^4`, `-1000 <= nums[i] <= 1000`, `1 <= k <= number of distinct elements`.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        
        int ans[] =new int[k];
        PriorityQueue<Pair> q=new PriorityQueue<>((a,b)->b.f-a.f);
        HashMap<Integer,Pair> map= new HashMap<>();

        for(int i: nums){
            Pair p=map.getOrDefault(i,new Pair(i));
            p.f++;
            map.put(i,p);
        }

        q.addAll(map.values());

        int i=0;

        while(k>0 && !q.isEmpty()){
            ans[i++]=q.poll().e;
            k--;
        }

        return ans;
    }

    class Pair{

        int e;
        int f;

        public Pair(int e){
            this.e=e;
            f=0;
        }
    }
}
```

Count frequencies in a `HashMap<Integer, Pair>` (Pair holds element and frequency). Put all distinct pairs into a max-heap ordered by frequency, then poll `k` times to collect the answer.

## 3. Complexity
- Time: O(n + d log d) where d = distinct elements (worst case O(n log n)). Counting is O(n), `addAll` is d insertions at O(log d) each, k polls at O(log d) each.
- Space: O(d) for the map, pairs and heap

## 4. What I Missed
- The target is O(n). Frequencies are bounded integers in `[1, n]`, so bucket sort by frequency removes the heap entirely. This is the key observation I missed.
- Heap variants I did not weigh: a min-heap capped at size `k` gives O(n log k) and O(k) heap space, better than heaping all `d` elements when `k << d`.
- `getOrDefault(i, new Pair(i))` allocates a new `Pair` on every element, even when the key exists. The `put` after the first insertion is redundant. (Same habit as `getOrDefault(..., new ArrayList<>())` in Group Anagrams. Use `computeIfAbsent` or `merge`.)
- `b.f - a.f` works here (counts are small and non-negative) but subtraction comparators are a latent overflow bug. Use `Integer.compare(b.f, a.f)`.
- `PriorityQueue.addAll` inserts one by one (O(d log d)); it does not heapify in O(d).
- Constraint `-1000 <= nums[i] <= 1000` allows a plain `int[2001]` count array (offset by 1000) instead of a `HashMap`.
- Style: `Pair` should be a `static` nested class (a non-static inner class carries a hidden reference to the outer instance); fields `e`/`f` are cryptic; `k` and `i` are two counters for the same thing, and `k` is mutated.

## 5. Optimal Approach
Count frequencies, then bucket sort: `buckets[f]` holds all values that occur exactly `f` times, where `f` ranges over `1..n`. Walk the buckets from `n` down to `1`, collecting values until `k` are taken. No comparisons are needed, so it is O(n) time and O(n) space.

Practical fallback: min-heap of size `k` (O(n log k)). Quickselect is average O(n) but mutates data and is not worth the complexity here.

## 6. Optimal Java Code

```java
class Solution {
    @SuppressWarnings("unchecked")
    public int[] topKFrequent(int[] nums, int k) {
        Map<Integer, Integer> freq = new HashMap<>();
        for (int num : nums) freq.merge(num, 1, Integer::sum);

        // buckets[f] = values appearing exactly f times
        List<Integer>[] buckets = new List[nums.length + 1];
        for (Map.Entry<Integer, Integer> e : freq.entrySet()) {
            int f = e.getValue();
            if (buckets[f] == null) buckets[f] = new ArrayList<>();
            buckets[f].add(e.getKey());
        }

        int[] ans = new int[k];
        int idx = 0;
        for (int f = nums.length; f >= 1 && idx < k; f--) {
            if (buckets[f] == null) continue;
            for (int num : buckets[f]) {
                ans[idx++] = num;
                if (idx == k) break;
            }
        }
        return ans;
    }
}
```

Constraint-exploiting variant: replace the `HashMap` with `int[] count = new int[2001]` using `num + 1000` as the index. Only valid for the stated range.

## 7. Quick Revision
Frequency is an integer between 1 and n, so index buckets by frequency and read from the top: O(n), no heap. If a heap is wanted, use a min-heap of size k (O(n log k)).

## 8. Pattern
- Primary: Bucket Sort on frequency (Top-K)
- Secondary: Hash Map counting, Heap / Priority Queue (min-heap of size k), Quickselect

# <span style="color:orange">  Encode and Decode Strings </span>

## 1. Problem Statement
LeetCode 271 / NeetCode "Encode and Decode Strings". Implement `encode(List<String>)` -> one `String`, and `decode(String)` -> the original `List<String>`, so that `decode(encode(strs))` equals `strs`.
Constraints: `0 <= strs.length < 100`, `0 <= strs[i].length < 200`, characters are any of the 256 ASCII characters. Follow-up: make it work for any possible character set.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {

final String pre ="pre";
final String suf ="suf";



    public String encode(List<String> strs) {
        StringBuilder str=new StringBuilder();

        for(String s: strs){

            str.append(pre+s+suf);
        }

        return str.toString();
    }

    public List<String> decode(String str) {

          List<String> ans =new ArrayList<>();

         if(str ==null || str.isEmpty())return ans; 

          String arr[] = str.split("suf");  
            for(String s:arr){
                ans.add(s.substring(3,s.length()));
            }

          return ans;
    }
}
```

Wrap every string as `"pre" + s + "suf"` and concatenate. To decode, split the whole string on `"suf"` and strip the first 3 characters (`"pre"`) from each piece.

## 3. Complexity
- Time: O(m) for each of encode and decode (m = total characters)
- Space: O(m + n) (n = number of strings)
- Complexity is fine, but the solution is **incorrect** (see below).

## 4. What I Missed
- **Delimiter collision:** any string containing `"suf"` breaks decoding, and the constraint allows any characters. Examples (traced by hand):
  - `["suf"]` -> `"presufsuf"` -> `split("suf")` gives `["pre"]` (trailing empty tokens are dropped) -> decodes to `[""]`. Silent wrong answer.
  - `["asufb"]` -> `"preasufbsuf"` -> `["prea", "b"]` -> `"b".substring(3, 1)` throws `StringIndexOutOfBoundsException`.
- A longer or rarer delimiter only lowers the collision probability; it can never guarantee correctness for arbitrary input. This is the "naive" approach from NeetCode's Hint 1.
- The `"pre"` prefix does nothing useful; it is just stripped again, and adds 3 chars per string.
- `split` takes a regex and silently drops trailing empty strings. Fine for literal text here, but another source of subtle bugs.
- Never tested with adversarial input (a string containing my own delimiter), nor with `[]`, `[""]`, `["", ""]` systematically.
- Missed the follow-up: "any possible character set" rules out every in-band delimiter.

## 5. Optimal Approach
Length-prefix encoding. Write each string as `<length>#<string>`. To decode, read digits up to the next `#`, parse the length `L`, then take exactly the next `L` characters and jump past them. The payload is never scanned, so `#`, digits or any other characters inside the strings cannot confuse the parser. Works for any character set.

## 6. Optimal Java Code

```java
class Solution {

    public String encode(List<String> strs) {
        StringBuilder sb = new StringBuilder();
        for (String s : strs) {
            sb.append(s.length()).append('#').append(s);
        }
        return sb.toString();
    }

    public List<String> decode(String str) {
        List<String> res = new ArrayList<>();
        int i = 0;
        while (i < str.length()) {
            int j = str.indexOf('#', i);              // end of the length field
            int len = Integer.parseInt(str.substring(i, j));
            i = j + 1;                                // start of the payload
            res.add(str.substring(i, i + len));
            i += len;                                 // jump over the payload
        }
        return res;
    }
}
```

Complexity: O(m) time per call, O(m + n) space.

## 7. Quick Revision
If the data can contain any character, no delimiter is safe, so store the length instead: `len#payload`. Read the length, then skip exactly that many characters, so you never inspect the payload.
Test every encoding with inputs containing your own special tokens, plus `[]`, `[""]` and `["", ""]`.

## 8. Pattern
- Primary: Length-prefixed encoding (serialization / framing)
- Secondary: String parsing with index pointers, Design

# <span style="color:orange">  Product of Array Except Self </span>

## 1. Problem Statement
LeetCode 238 / NeetCode "Products of Array Except Self". Given an integer array `nums`, return `output` where `output[i]` is the product of all elements of `nums` except `nums[i]`. Each product fits in a 32-bit integer. Follow-up: solve in O(n) without division.
Constraints: `2 <= nums.length <= 100,000`, `-30 <= nums[i] <= 30`, any prefix or suffix product fits in 32 bits.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public int[] productExceptSelf(int[] nums) {
        
         int n= nums.length;
        int ans[]= new int[n];
        int lp[]=new int[n];
        int rp[]=new int[n];
        int zeroC=0;

        for(int i=0;i<n;i++){

            if(i==0)lp[i]=1;
            else if(nums[i-1]!=0)
                lp[i]=lp[i-1]*nums[i-1];
            else
                lp[i]=lp[i-1];

            if(nums[i]==0)
                zeroC++;        
        }
        if(zeroC>1)return ans;

        for(int i=n-1;i>=0;i--){
            if(i==n-1)rp[i]=1;
            else if(nums[i+1]!=0)
                rp[i]=rp[i+1]*nums[i+1];
            else 
                rp[i]=rp[i+1];    
        }

        for(int i=0;i<n;i++){

            int v =0;

            if(zeroC>0){
                if(nums[i]==0){
                    v= lp[i]*rp[i];
                }
            }
            else
                 v= lp[i]*rp[i];

            ans[i]=v;

        }   


        return ans;
    }
}
```

Build a left-product array `lp` and right-product array `rp` that skip zeros, and count zeros. More than one zero: return all zeros. Exactly one zero: only the zero's position gets `lp*rp` (the product of all nonzeros), everything else is 0. No zeros: `ans[i] = lp[i] * rp[i]`.

## 3. Complexity
- Time: O(n) (three passes)
- Space: O(n) auxiliary (two extra arrays, `lp` and `rp`, besides the output)
- Correct on all cases I traced (`[1,2,4,6]`, `[-1,0,1,2,3]`, `[0,0]`, `[0,4]`).

## 4. What I Missed
- **Zero handling is unnecessary.** `lp[i] * rp[i]` is already the product of everything except `nums[i]`, so zeros need no special case. Plain prefix and suffix products give the right answer for zero, one or many zeros. My zero-skipping branches only change values at indices whose answer is 0 anyway and is never read; this is division-style thinking (count zeros, special-case) grafted onto prefix/suffix.
- **Missed the O(1) extra space version:** store prefix products directly in the output array, then sweep right to left with one running `suffix` variable. No `lp` or `rp` arrays.
- More branching means more bug surface (zeroC cases, `v`, three loops with conditionals), for no gain.
- Did not state why the one-zero case is safe: at the zero's index, `lp` and `rp` contain no zero, so their product is exactly the answer.
- The `v` temp and final `ans[i] = v` are redundant (`ans` is already zero-initialized).

## 5. Optimal Approach
`output[i] = (product of everything left of i) * (product of everything right of i)`. Left products accumulate: `L[i] = L[i-1] * nums[i-1]`, so one left-to-right pass fills them (store directly in `ans`). Then sweep right to left keeping a running `suffix` product, multiplying it into `ans[i]` before including `nums[i]`. No division, no zero special-casing.

## 6. Optimal Java Code

```java
class Solution {
    public int[] productExceptSelf(int[] nums) {
        int n = nums.length;
        int[] ans = new int[n];

        ans[0] = 1;
        for (int i = 1; i < n; i++) {
            ans[i] = ans[i - 1] * nums[i - 1];   // product of everything left of i
        }

        int suffix = 1;
        for (int i = n - 1; i >= 0; i--) {
            ans[i] *= suffix;                    // times product of everything right of i
            suffix *= nums[i];
        }
        return ans;
    }
}
```

Complexity: O(n) time, O(1) auxiliary space (the output array is not counted).

## 7. Quick Revision
"Everything except me" = (everything to my left) x (everything to my right), so no division and no zero special cases. Prefix products go in the output array, then a right-to-left running suffix variable finishes it in O(1) extra space.

## 8. Pattern
- Primary: Prefix / Suffix products
- Secondary: In-place reuse of the output array for O(1) extra space, Array scan with running variable

# <span style="color:orange">  Longest Consecutive Sequence </span>

## 1. Problem Statement
LeetCode 128 / NeetCode "Longest Consecutive Sequence". Given an integer array `nums`, return the length of the longest sequence of elements where each is exactly 1 greater than the previous. Elements need not be adjacent in the array. **Must run in O(n) time.**
Constraints: `0 <= nums.length <= 100,000`, `-10^9 <= nums[i] <= 10^9`.

## 2. My Approach
Two submissions (both unmodified).

**Attempt 1: sorting**

```java
class Solution {
    public int longestConsecutive(int[] nums) {
        
        int ans= 0;
        int n=nums.length;

        Arrays.sort(nums);

        for(int i=0;i<n;){
            int c=1;
            int j=i;
            while( j+1<n ){

                if(nums[j]==nums[j+1])
                    j++;
                else if(nums[j]+1 == nums[j+1]) 
                    {
                        c++;
                        j++;
                    }
                else break;    
            }
            if(i==j)i++;
            else i=j;

            ans= Math.max(ans, c);

        }

        return ans;
    }
}
```

Sort, then sweep: from `i`, extend `j` over duplicates (same value) and +1 steps (count them), stop at a gap, record the run length, and restart from `j`.

**Attempt 2: HashSet + scan of the whole value range**

```java
class Solution {
    public int longestConsecutive(int[] nums) 
    {
        int max=Integer.MIN_VALUE;
        int min=Integer.MAX_VALUE;
        HashSet<Integer> set=new HashSet<>();

        for(int i:nums)    
        {
            max=Math.max(max,i);
            min=Math.min(min,i);
            set.add(i);
        }

        int ans=0;
        int curMax=0;    
        for(int i=min;i<=max;i++)
        {
            if(set.contains(i))curMax++;
            else curMax=0;

            ans=Math.max(ans,curMax);

        }


        return ans;
    }
}
```

Put everything in a set, then walk every integer from `min` to `max`, counting the current streak of values present in the set.

## 3. Complexity
- Attempt 1: O(n log n) time (sort dominates), O(1) auxiliary space, mutates the input. Correct, but violates the O(n) requirement.
- Attempt 2: O(n + R) time where R = max - min + 1 (up to about 2 x 10^9), O(n) space. Correct, but cost depends on the value range, not on n. Not O(n).

## 4. What I Missed
- **The O(n) requirement is in the statement.** Sorting is O(n log n), so Attempt 1 is excluded by the problem itself.
- **Attempt 2 iterates over the value range, not the data.** `nums = [-10^9, 10^9]` has n = 2 but needs about 2 x 10^9 loop iterations with boxed `HashSet.contains` calls. Also `i <= max` would loop forever if `max == Integer.MAX_VALUE` (int overflow), outside these constraints but a real hazard.
- **Key observation missed:** a number `x` starts a run only if `x - 1` is not in the set. Each maximal run has exactly one start, so walking forward only from starts visits every element at most twice: O(n).
- **Trap:** iterate over the `HashSet`, not the original array. With many duplicates of a run's start, iterating `nums` re-walks the same run for every duplicate (back to O(n^2)).
- Attempt 1 details: restarting at `i = j` re-processes the last element of each run, and the nested loop with three branches is more complex than needed. A single pass (skip equal, `cur++` on +1, else reset) does the same job.
- Union-Find also solves it in near-O(n), but is heavier than the hash-set approach and not worth it here.

## 5. Optimal Approach
Put all numbers in a `HashSet`. For each distinct number `x` in the set: if `x - 1` is in the set, skip it (not a start). Otherwise count upward (`x+1`, `x+2`, ...) while the numbers exist, and track the maximum length. Every element is touched O(1) times in total, so O(n) time and O(n) space.

## 6. Optimal Java Code

```java
class Solution {
    public int longestConsecutive(int[] nums) {
        Set<Integer> set = new HashSet<>(nums.length * 2);
        for (int num : nums) set.add(num);

        int best = 0;
        for (int num : set) {                        // iterate the set, not nums (duplicates!)
            if (set.contains(num - 1)) continue;     // not the start of a run
            int len = 1;
            while (set.contains(num + len)) len++;
            best = Math.max(best, len);
        }
        return best;
    }
}
```

Sorting fallback if O(n log n) is acceptable:

```java
Arrays.sort(nums);
int best = nums.length == 0 ? 0 : 1, cur = 1;
for (int i = 1; i < nums.length; i++) {
    if (nums[i] == nums[i - 1]) continue;
    cur = (nums[i] == nums[i - 1] + 1) ? cur + 1 : 1;
    best = Math.max(best, cur);
}
```

## 7. Quick Revision
Only a number with no predecessor (`x - 1` absent) can start a run, so walk forward from run starts only, using a HashSet: every element is visited O(1) times.
Never loop over the value range, only over the elements present; and iterate the set, not the array, so duplicates cannot redo work.

## 8. Pattern
- Primary: Hash Set (sequence-start detection, avoid repeated work)
- Secondary: Sorting + linear scan (O(n log n) fallback), Union-Find (alternative)
