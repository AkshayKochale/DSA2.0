# <span style="color:orange">  Best Time to Buy and Sell Stock </span>

## 1. Problem Statement
LeetCode 121 / NeetCode "Best Time to Buy and Sell Stock" (`buy-and-sell-crypto`). Given an integer array `prices` where `prices[i]` is the price on day `i`, choose a single day to buy and a **different, later** day to sell. Return the maximum profit; if no profitable transaction exists, return `0`.
Examples: `[10,1,5,6,7,1]` -> `6` (buy at 1, sell at 7); `[10,8,7,5,2]` -> `0`.
Constraints: `1 <= prices.length <= 100`, `0 <= prices[i] <= 100`. Recommended: O(n) time, O(1) space.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public int maxProfit(int[] prices) {
        
        int ans = 0;
           int i=0; 
           while(i<prices.length){
                int cur =prices[i];
                int j=i+1;
                while(j<prices.length && prices[i]<=prices[j]){
                    ans = Math.max(ans,prices[j]-prices[i]);
                    j++;
                }
                i=j;
           }

        return ans;
    }
}
```

Treat `i` as the buy day. Scan `j` forward while the price stays at least `prices[i]`, tracking the best profit. When a lower price at `j` appears, that day is a better buy than `i` from then on, so jump `i = j` and continue.

## 3. Complexity
- Time: O(n) (each index is visited at most about twice, since `i` jumps to where `j` stopped)
- Space: O(1)
- Correct. Hand-traced on both examples, a single price, a strictly decreasing array, and equal prices.

## 4. What I Missed
No correctness problems; the solution is already O(n) time and O(1) space. Remaining points:
- **Why `i = j` is safe was not stated (dominance argument):** every day between `i` and `j` has price >= `prices[i]`, so buying at `i` is at least as good as buying at any of them; and once `prices[j] < prices[i]`, buying at `j` beats buying at `i` for every sale after `j`. No better pair is skipped.
- **The nested loops look O(n^2)** but are O(n): the inner loop's stopping index becomes the next `i`, so no index is rescanned more than a constant number of times. This amortized argument was not written down.
- **Simpler formulation:** for each day as the *sell* day, the best buy is the minimum price seen before it, so keep a running minimum and update `best = max(best, price - minPrice)` in one pass. It exposes the structure (prefix minimum) directly.
- Equivalent sliding-window form of the same idea: `l` = buy day, `r` = sell day; if `prices[r] < prices[l]` then `l = r`, else update the profit.
- Unused variable `int cur = prices[i];`.
- Link to remember: profit over one transaction is the maximum sum of a contiguous run of daily price differences (Kadane's algorithm / Maximum Subarray).
- Good, keep: answer starts at 0, so a falling market correctly returns 0; the `<=` comparison harmlessly includes equal prices.

## 5. Optimal Approach
Profit = sell - buy. For a fixed sell day, profit is largest when the buy price is the lowest price on any earlier day. So scan once, keeping `minPrice` (the lowest price so far including today) and `best` (the largest `price - minPrice` seen). O(n) time, O(1) space. `best` starts at 0, so "no transaction" is covered.

## 6. Optimal Java Code

```java
class Solution {
    public int maxProfit(int[] prices) {
        int minPrice = Integer.MAX_VALUE;     // lowest price seen so far (best buy)
        int best = 0;
        for (int price : prices) {
            minPrice = Math.min(minPrice, price);
            best = Math.max(best, price - minPrice);
        }
        return best;
    }
}
```

Sliding-window variant (same idea as my submission, in a single loop):

```java
int l = 0, best = 0;                          // l = buy day
for (int r = 1; r < prices.length; r++) {     // r = sell day
    if (prices[r] < prices[l]) l = r;         // lower price: better buy day from now on
    else best = Math.max(best, prices[r] - prices[l]);
}
```

## 7. Quick Revision
For each possible sell day, the best buy is the lowest price before it, so scan once with a running minimum: `best = max(best, price - minPrice)`.
Start `best` at 0 (no trade allowed). The same idea is a sliding window: when a lower price appears, move the buy pointer to it.

## 8. Pattern
- Primary: Running minimum / prefix minimum (single pass)
- Secondary: Sliding Window (two pointers), Kadane's algorithm on daily differences, Dynamic Programming (track the best state so far)

# <span style="color:orange">  Longest Substring Without Repeating Characters </span>

## 1. Problem Statement
LeetCode 3 / NeetCode "Longest Substring Without Duplicates". Given a string `s`, return the length of the longest substring (contiguous) that contains no duplicate characters.
Examples: `"zxyzxyz"` -> `3` (`"xyz"`); `"xxxx"` -> `1`.
Constraints: `0 <= s.length <= 50,000`; `s` may consist of printable ASCII characters. Recommended: O(n) time, O(m) space (m = number of unique characters).

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public int lengthOfLongestSubstring(String s) {

        int ans =0; 
        HashSet<Character> set = new HashSet<>();
        int j=0;
        for(int i=0;i<s.length();i++){
            char c = s.charAt(i);
            while(set.contains(c)){
                set.remove(s.charAt(j));
                j++;
            }
            set.add(c);
            ans = Math.max(ans,i-j+1);
        }

       return ans; 
    }
}
```

Sliding window `[j, i]` kept free of duplicates with a `HashSet` of the window's characters. For each new character, shrink from the left (`j++`, removing from the set) until it is no longer in the window, then add it and update the best length.

## 3. Complexity
- Time: O(n) (each index is added to and removed from the set at most once)
- Space: O(m), m <= 95 printable characters here
- Correct. Hand-traced on `"zxyzxyz"` (3), `"xxxx"` (1) and the empty string (0).

## 4. What I Missed
No correctness problems; this is the standard optimal sliding window. Remaining points:
- **Invariant not stated:** after the `while` loop the set holds exactly the characters of `[j, i]` and the window has no duplicates; the new character is added only after the duplicate is gone.
- **Amortized O(n) not stated:** the nested `while` looks O(n^2), but `j` only moves forward and every character leaves the set at most once.
- **Jump instead of shrinking one step at a time:** store each character's last index; on a repeat, move `left` straight to `max(left, lastIndex + 1)`. One pass, no inner loop, no removals. The `max` matters: for `"abba"`, the final `'a'` has a last index *before* the window start and must not move `left` backwards.
- Since the input is printable ASCII, an `int[128]` array replaces the `HashSet<Character>` (no boxing, no hashing).
- Naming: `i` is the right end and `j` the left end, the reverse of the usual `left`/`right` reading order.
- Good, keep: the length is computed as `i - j + 1` after the window is valid; the empty string correctly returns 0.

## 5. Optimal Approach
Intuition: a substring is valid when it has no repeated character. Keep a window `[left, right]` that is always valid. Move `right` forward; when `s[right]` already appears inside the window, the only fix is to push `left` just past that earlier occurrence (anything smaller still contains the duplicate). `right` never moves backward and `left` never moves backward, so each index is processed once: O(n). Brute force restarting from every start index repeats work.
Implementation: store, for each character, the index after its last occurrence (`lastSeen`, 0 = never seen). For each `right`, set `left = max(left, lastSeen[c])`, then `lastSeen[c] = right + 1`, then update `best = max(best, right - left + 1)`.

## 6. Optimal Java Code

```java
class Solution {
    public int lengthOfLongestSubstring(String s) {
        int[] lastSeen = new int[128];       // index + 1 of the last occurrence; 0 = never seen
        int best = 0, left = 0;
        for (int right = 0; right < s.length(); right++) {
            char c = s.charAt(right);
            left = Math.max(left, lastSeen[c]);   // jump past the previous occurrence if it is in the window
            lastSeen[c] = right + 1;
            best = Math.max(best, right - left + 1);
        }
        return best;
    }
}
```

For non-ASCII input use `new int[256]` or a `HashMap<Character, Integer>`.

## 7. Quick Revision
Keep a window with no duplicates: when the new character repeats inside it, move `left` just past the earlier occurrence (`left = max(left, lastSeen[c])`), never backward.
Both pointers only move forward, so O(n); length is `right - left + 1`.

## 8. Pattern
- Primary: Sliding Window (variable size, no duplicates)
- Secondary: Hash Set / last-seen index map, Two Pointers

# <span style="color:orange">  Longest Repeating Character Replacement </span>

## 1. Problem Statement
LeetCode 424 / NeetCode "Longest Repeating Substring With Replacement". Given a string `s` of uppercase English letters and an integer `k`, you may replace up to `k` characters with any uppercase letter. Return the length of the longest substring that can be made of one repeated character.
Examples: `s = "XYYX", k = 2` -> `4`; `s = "AAABABB", k = 1` -> `5`.
Constraints: `1 <= s.length <= 100,000`, `0 <= k <= s.length`, only uppercase English letters. Recommended: O(n) time, O(m) space (m = number of unique characters).

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public int characterReplacement(String s, int k) {

           
        int n = s.length();
        if(k>=n)return n;

        HashMap<Character,Pair> map = new HashMap<>();
        PriorityQueue<Pair> q = new PriorityQueue<>((a,b)->b.f-a.f);

        int ans =0;
        int i=0,j =0;
        

        while(i<n){
            char c= s.charAt(i);
            Pair p = map.getOrDefault(c,new Pair(c));
            p.f++;
            map.put(c,p);

            if(p.f>1)q.remove(p);
            q.add(p);

            while(true){

                // find out char with max fre
                char mfc = q.peek().c;
                int mf = q.peek().f;

                // cur total len
                int ctl = i-j+1;

                if(k< ctl - mf){
                    
                    char rc= s.charAt(j++);
                    Pair rp = map.get(rc);
                     q.remove(rp);
                    rp.f--;
                    
                    if(rp.f==0){
                        map.remove(rc);
                        q.remove(rp);
                    }else q.add(rp);
                    continue;
                }   
                ans = Math.max(ans,ctl);
                break;

            }
            i++;
        }

        return ans ;
    }

    class Pair{

        char c;
        int f;

        public Pair(char c){
            this.c= c;this.f=0;
        }
    }
}
```

Sliding window `[j, i]`. A `HashMap` holds each character's frequency in the window (as a `Pair`) and a max-heap orders those pairs by frequency, so the heap top is the window's most frequent character. A window is valid when `length - maxFrequency <= k` (the characters that are not the most frequent are the ones replaced). If invalid, shrink from the left until valid, then record the length.

## 3. Complexity
- Time: O(n * m) with m <= 26 (every `PriorityQueue.remove(Object)` is a linear scan of at most 26 entries), so effectively O(n) but with heavy constants (maps, heap, objects).
- Space: O(m)
- Correct. Hand-traced on `"XYYX"` with `k = 2` (4).

## 4. What I Missed
- **A heap and a map are overkill for 26 letters.** An `int[26]` count array gives the window's counts, and finding the maximum by scanning 26 slots costs the same as `PriorityQueue.remove(Object)`'s linear scan, without objects or boxing.
- **Key trick missed: the maximum frequency never needs to decrease.** Keep `maxFreq` as the largest single-character count seen in *any* window so far. The answer can only improve when a new, larger `maxFreq` appears, so a stale `maxFreq` never produces a wrong answer. This removes the need to track the exact current maximum at all, and gives true O(n) with O(1) work per step.
- **The window can slide instead of shrinking in a loop:** when `length - maxFreq > k`, move `left` by exactly one (an `if`, not a `while`); the window length then stays the same until a better `maxFreq` is found.
- **Heap keys were mutated while still inside the heap:** `p.f++` runs before `q.remove(p)`. It works only because `remove(Object)` finds the element by a linear identity scan, not by heap order; this is fragile. In the shrink path you correctly remove, then change `f`, then re-add.
- Redundant work: the second `q.remove(rp)` after `rp.f == 0` is a no-op (it was already removed); `mfc` is never used; `if (k >= n) return n` is not needed (the general logic already returns `n` in that case).
- Alternative simpler approach: for each letter `A..Z`, run a window that allows at most `k` characters different from that letter; O(26 n), easy to reason about.
- Why replacing the most frequent character is optimal (Hint 2) was not stated: replacements needed = `window length - count of most frequent character`.
- Good, keep: the validity test `k < length - maxFrequency` (same formula as the optimal solution), and shrinking from the left as the window grows.

## 5. Optimal Approach
Intuition: for any window, the cheapest way to make it uniform is to keep its most frequent character and replace the rest, so the replacements needed = `length - maxFrequency`. A window is valid when that is `<= k`. Expand `right`; keep counts in `int[26]` and a running `maxFreq`. If `(right - left + 1) - maxFreq > k`, the window is invalid: slide it by moving `left` one step (decrement that letter's count). Because `maxFreq` is only ever raised, the window length grows only when a genuinely better window exists, so the final window length is the answer. One pass, O(n) time, O(26) space.

## 6. Optimal Java Code

```java
class Solution {
    public int characterReplacement(String s, int k) {
        int[] count = new int[26];
        int left = 0, maxFreq = 0, best = 0;
        for (int right = 0; right < s.length(); right++) {
            maxFreq = Math.max(maxFreq, ++count[s.charAt(right) - 'A']);
            if ((right - left + 1) - maxFreq > k) {        // needs more than k replacements
                count[s.charAt(left) - 'A']--;
                left++;                                    // slide: window length stays the same
            }
            best = Math.max(best, right - left + 1);
        }
        return best;
    }
}
```

## 7. Quick Revision
Replacements needed for a window = `length - (count of its most frequent letter)`; the window is valid if that is `<= k`.
Slide a window with an `int[26]` and a never-decreasing `maxFreq`: if `length - maxFreq > k`, move `left` by one. Answer = the largest window length.

## 8. Pattern
- Primary: Sliding Window (variable size, bounded number of replacements)
- Secondary: Frequency counting (`int[26]`), "max frequency never decreases" trick, Heap (overkill alternative)

# <span style="color:orange">  Permutation in String </span>

## 1. Problem Statement
LeetCode 567 / NeetCode "Permutation in String". Given two strings `s1` and `s2`, return `true` if `s2` contains a permutation of `s1` as a substring, otherwise `false`. Both strings contain only lowercase letters.
Examples: `s1 = "abc", s2 = "lecabee"` -> `true` (`"cab"`); `s1 = "abc", s2 = "lecaabee"` -> `false`.
Constraints: `1 <= s1.length, s2.length <= 10,000`. Recommended: O(n) time, O(1) space.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public boolean checkInclusion(String s1, String s2) {

        if(s1.length()>s2.length())return false;

        HashMap<Character,Integer> m1 = new HashMap<>();
        for(int i=0;i<s1.length();i++)
            m1.put(s1.charAt(i),m1.getOrDefault(s1.charAt(i),0)+1);

        HashMap<Character,Integer> m2 = new HashMap<>();    
        for(int i=0;i<s1.length();i++){
            m2.put(s2.charAt(i),m2.getOrDefault(s2.charAt(i),0)+1);
        }

        int j=0;
        
        for(int i=s1.length();i<s2.length();i++){

               if(m1.equals(m2)) return true;

               m2.put(s2.charAt(i),m2.getOrDefault(s2.charAt(i),0)+1);
               m2.put(s2.charAt(j),m2.getOrDefault(s2.charAt(j),0)-1);
               if(m2.get(s2.charAt(j))==0)m2.remove(s2.charAt(j));
                j++;
                
        }

        return m1.equals(m2);   
    }
}
```

A permutation of `s1` has exactly the same character counts as `s1`. Build the count map of `s1` (`m1`) and of the first window of `s2` (`m2`), then slide a fixed-size window (length of `s1`) across `s2`: add the entering character, remove the leaving one (deleting the key when its count reaches 0), and compare the maps. The final check after the loop covers the last window.

## 3. Complexity
- Time: O(n * 26) = O(n), since each `HashMap.equals` compares at most 26 entries per slide
- Space: O(26) = O(1)
- Correct. Hand-traced on both examples (`true`, `false`), `s1` longer than `s2`, and equal lengths.

## 4. What I Missed
- **Count maps are heavier than needed:** the alphabet is `a..z`, so two `int[26]` arrays replace the `HashMap`s (no boxing, no hashing). `Arrays.equals` on the arrays is the same O(26) per step; a `matches` counter makes each slide O(1).
- **Subtle correctness point:** the maps compare equal only because zero-count keys are removed. A leftover key with value 0 would make `equals` return false for a real match. It is right in your code, but fragile and worth stating.
- **`matches` counter idea:** track how many of the 26 letters currently have equal counts in both windows. When a count changes, adjust `matches` only for that letter. The window is a permutation exactly when `matches == 26`. This gives true O(1) per slide.
- The separate pointer `j` is not needed: for a fixed window, the character leaving is always at `right - s1.length()`.
- The final `m1.equals(m2)` after the loop is required (the loop checks a window before sliding, so the last window would otherwise be missed). It is correct, but easy to get wrong; an alternative is to check after each slide.
- Brute-force alternatives not mentioned: generating all permutations of `s1` is O(n!); sorting each window and comparing is O(n * len log len).
- Code is duplicated in three places (building counts); an array and a single loop removes that.
- Good, keep: the early `s1.length() > s2.length()` return, the fixed-size window idea, and removing zero keys.

## 5. Optimal Approach
Intuition: two strings are permutations of each other exactly when they have the same character frequencies (same idea as Valid Anagram). So we do not generate permutations; we look for a substring of `s2` of length `s1.length()` whose frequency table equals `s1`'s. Because the window length is fixed, the window slides one step at a time: one character enters on the right, one leaves on the left, so counts update in O(1). Use `int[26]` for `need` (`s1`) and `window`. Keep `matches` = number of letters (of 26) where `need[c] == window[c]`. When a letter's count changes, adjust `matches` only for that letter: it becomes equal (`matches++`), or stops being equal (`matches--`). Return `true` whenever `matches == 26`. O(n) time, O(1) space.

## 6. Optimal Java Code

```java
class Solution {
    public boolean checkInclusion(String s1, String s2) {
        int n1 = s1.length(), n2 = s2.length();
        if (n1 > n2) return false;

        int[] need = new int[26];
        int[] window = new int[26];
        for (int i = 0; i < n1; i++) {
            need[s1.charAt(i) - 'a']++;
            window[s2.charAt(i) - 'a']++;
        }

        int matches = 0;                                    // letters whose counts are equal
        for (int c = 0; c < 26; c++) if (need[c] == window[c]) matches++;

        for (int right = n1; right < n2; right++) {
            if (matches == 26) return true;

            int in = s2.charAt(right) - 'a';                // letter entering the window
            window[in]++;
            if (window[in] == need[in]) matches++;
            else if (window[in] == need[in] + 1) matches--;

            int out = s2.charAt(right - n1) - 'a';          // letter leaving the window
            window[out]--;
            if (window[out] == need[out]) matches++;
            else if (window[out] == need[out] - 1) matches--;
        }
        return matches == 26;                               // last window
    }
}
```

## 7. Quick Revision
A permutation means identical character counts, so slide a fixed window (length of `s1`) over `s2` and compare `int[26]` counts.
Track `matches` = how many of the 26 letters have equal counts; each slide updates only two letters (entering and leaving), so each step is O(1).

## 8. Pattern
- Primary: Sliding Window (fixed size) with frequency counting
- Secondary: Hash map / `int[26]` counts, Anagram check (Valid Anagram), "matches" counter trick

# <span style="color:orange">  Minimum Window Substring </span>

## 1. Problem Statement
LeetCode 76 / NeetCode "Minimum Window With Characters". Given strings `s` and `t`, return the shortest substring of `s` that contains every character of `t`, including duplicates. If no such substring exists, return `""`. The correct output is guaranteed to be unique.
Examples: `s = "OUZODYXAZV", t = "XYZ"` -> `"YXAZ"`; `s = "xyz", t = "xyz"` -> `"xyz"`; `s = "x", t = "xy"` -> `""`.
Constraints: `1 <= s.length, t.length <= 100,000`; letters are uppercase and lowercase English. Recommended: O(n + m) time, O(k) space (k = unique characters).

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public String minWindow(String s, String t) {

           
         String ans = "";
         int min = Integer.MAX_VALUE;   
         int n =s.length();
        if(t.length()>s.length())return ans;
        HashMap<Character,Integer> checkMap = new HashMap<>();
        HashMap<Character,Integer> map = new HashMap<>();

        for(int i=0;i<t.length();i++)
            checkMap.put(t.charAt(i),checkMap.getOrDefault(t.charAt(i),0)+1);

        int f=0,r=0;

        while(f<n){
            char c = s.charAt(f);

            if(checkMap.containsKey(c))
                map.put(c,map.getOrDefault(c,0)+1);

            while(r<=f && isSame(checkMap,map)){
                char rm =s.charAt(r);

                    if(f-r+1<min){
                        min = f-r+1;
                        ans = s.substring(r,f+1);
                    }

                if(checkMap.containsKey(rm))
                    map.put(rm,map.getOrDefault(rm,0) - 1);
               
                r++;
            }    
            f++;
        }
        

        return ans;
    }

    static boolean isSame(HashMap<Character,Integer> m1,HashMap<Character,Integer> m2)
    {
           Set<Character> s1= m1.keySet();
             Set<Character> s2= m2.keySet();
         
         if(s1.size()!=s2.size())return false;

         for(Character c:s1)
         {
             if(m1.get(c)>m2.get(c))return false;
         }
         
         return true;
    }
}
```

Variable-size sliding window `[r, f]`. `checkMap` holds the required counts from `t`; `map` holds counts of `t`'s characters inside the window. Expand `f`; whenever the window covers `t` (`isSame`: every required count is met), record it if it is the shortest so far, then shrink from the left (`r++`) and re-check until it stops covering.

## 3. Complexity
- Time: O((n + m) * k) with k <= 52 distinct letters: each `isSame` call scans up to k entries and runs once per `f` step and once per shrink step. Effectively linear, but with heavy constants (boxed maps).
- Space: O(k)
- Correct. Hand-traced on Example 1 (`"YXAZ"`), `t` longer than `s`, and duplicate letters in `t`.

## 4. What I Missed
- **Per-step validity check is O(k).** `isSame` rescans the maps every time. Keep a counter instead: `missing` = how many characters of `t` (with multiplicity) are still not covered. The window is valid exactly when `missing == 0`, and each add/remove updates it in O(1), giving true O(n + m).
- **`new substring` on every improvement.** `s.substring(r, f + 1)` copies the window each time a shorter one is found; worst case this can approach O(n^2) copying. Record only `bestStart` and `bestLen` and build the substring once at the end.
- **Subtle reliance in `isSame`:** `map` keeps keys whose count has dropped to 0, so `s1.size() == s2.size()` only means "every distinct character of `t` has been seen at least once", not "is currently in the window". The count comparison is what actually decides validity. It is right, but fragile and not obvious.
- `r <= f` in the shrink loop is redundant: a valid window always has `r <= f`.
- Two `HashMap<Character, Integer>` with boxing; since letters are ASCII, `int[128]` is simpler and faster.
- Did not state why shrinking is correct: once `[r, f]` covers `t`, any longer window with the same right end is not shortest; and for increasing `f`, the best left end only moves right, so both pointers move forward only (hence O(n)).
- Good, keep: the early `t.length() > s.length()` return, counting duplicates correctly (`>=` logic via counts), and recording every valid window while shrinking.

## 5. Optimal Approach
Intuition: expand the window on the right until it contains everything `t` needs; then shrink from the left as far as the window stays valid, recording the shortest; then continue expanding. For each right end, the shortest valid window is found by pushing `left` as far as possible, and that best `left` never moves backward as `right` grows, so each index is added once and removed once: O(n).
Implementation: `need[c]` = remaining requirement of letter `c` (negative means surplus in the window); `missing` = remaining characters still needed, starting at `t.length()`. Adding `s[right]`: if `need[c] > 0` it is a needed character, so `missing--`; then `need[c]--`. While `missing == 0`, record the window, then drop `s[left]`: `need[c]++`, and if it became positive a needed character was lost, so `missing++`; `left++`.

## 6. Optimal Java Code

```java
class Solution {
    public String minWindow(String s, String t) {
        if (t.length() > s.length()) return "";

        int[] need = new int[128];
        for (int i = 0; i < t.length(); i++) need[t.charAt(i)]++;

        int missing = t.length();                          // characters of t still not covered
        int left = 0, bestStart = 0, bestLen = Integer.MAX_VALUE;

        for (int right = 0; right < s.length(); right++) {
            if (need[s.charAt(right)]-- > 0) missing--;    // a needed character was covered

            while (missing == 0) {                         // window [left, right] covers t
                if (right - left + 1 < bestLen) {
                    bestLen = right - left + 1;
                    bestStart = left;
                }
                if (++need[s.charAt(left)] > 0) missing++; // dropped a needed character
                left++;
            }
        }
        return bestLen == Integer.MAX_VALUE ? "" : s.substring(bestStart, bestStart + bestLen);
    }
}
```

## 7. Quick Revision
Expand `right` until the window covers `t`, then shrink `left` while it still does, recording the shortest. Track coverage with `need[c]` and a `missing` counter (valid when `missing == 0`) instead of comparing maps.
Store `bestStart`/`bestLen` and build the substring once at the end.

## 8. Pattern
- Primary: Sliding Window (variable size, shrink while valid)
- Secondary: Frequency counting with a `missing` / `formed` counter, Hash map / `int[128]`

# <span style="color:orange">  Sliding Window Maximum </span>

## 1. Problem Statement
LeetCode 239 / NeetCode "Sliding Window Maximum". Given an integer array `nums` and a window size `k`, the window starts at the left edge and slides one position to the right until it reaches the right edge. Return the maximum element of the window at each position.
Example: `nums = [1,2,1,0,4,2,6], k = 3` -> `[2,2,4,4,6]`.
Constraints: `1 <= nums.length <= 100,000`, `-10,000 <= nums[i] <= 10,000`, `1 <= k <= nums.length`. Recommended: O(n log n) time, O(n) space or better.

## 2. My Approach
My submitted code (unmodified):

```java
class Solution {
    public int[] maxSlidingWindow(int[] nums, int k) {
        
        List<Integer> arr=new ArrayList<>();

        int max = Integer.MIN_VALUE;
        HashMap<Integer,Pair> map= new HashMap<>();
        
        PriorityQueue<Pair> q= new PriorityQueue<>((a,b)->b.v-a.v);

        for(int i=0;i<nums.length;i++){
           Pair p = new Pair(i,nums[i]);
           map.put(i,p);
            if(i>=k){
                 arr.add(q.peek().v);
                q.remove(map.get(i-k));
            }
            q.add(p);
        }
        arr.add(q.peek().v);

        int ans[]=new int[arr.size()];
        for(int i=0;i<ans.length;i++)
            ans[i]=arr.get(i);

         return ans;   
    }

    class Pair{

        int i;
        int v;
         public Pair(int i, int v){
               this.i=i;
               this.v=v; 
         }
    }
}
```

A max-heap of `Pair(index, value)` holds the current window. At each step `i >= k`, the heap top is the maximum of the window that just ended (indices `i-k .. i-1`), so record it, then remove the element that leaves the window (found through an index-to-`Pair` map) and add the new one. After the loop, record the last window's maximum.

## 3. Complexity
- Time: O(n * k) worst case: `PriorityQueue.remove(Object)` is a linear scan of the heap (up to `k` entries) plus O(log k) to fix the heap, done once per step. With `n = 10^5` and large `k` this is billions of operations.
- Space: O(n) (the map keeps every `Pair`, plus the result list)
- Correct. Hand-traced on the example (`[2,2,4,4,6]`); it produces exactly `n - k + 1` values.

## 4. What I Missed
- **Explicit removal from a heap is the bottleneck.** `remove(Object)` is O(k). A cheaper heap approach is **lazy deletion**: never remove; store `(value, index)`, add each new element, and before reading the max, pop the top while its index is `<= i - k` (outside the window). Each element is added once and popped at most once: O(n log n), meeting the recommended complexity.
- **Key observation for O(n):** when a new element `x` arrives, any *earlier* element in the window that is smaller than `x` can never be the maximum of any current or future window (`x` is larger and leaves the window later). So discard them. Keeping only a decreasing sequence of candidates gives a **monotonic deque** of indices with the maximum always at the front.
- The `map` stores every `Pair` for the whole run (O(n) space) only to find the pair to remove; the array `nums` plus indices removes the need for it. `int max` is unused. The result size is known up front (`n - k + 1`), so a plain `int[]` replaces the `ArrayList<Integer>` and the copy loop.
- The loop records the previous window's maximum *before* sliding, plus one extra record after the loop. It works but is easy to get wrong; recording after each insertion once `i >= k - 1` is simpler.
- Same family as Daily Temperatures and Largest Rectangle in Histogram: a monotonic structure that throws away elements that can never matter again.
- Good, keep: correct handling of the window boundary, the right number of windows, and removing the exact expired element by index (identity `Pair`).

## 5. Optimal Approach
Intuition: for the window maximum we only care about elements that could still become the maximum. An element that is smaller than a later element in the same window is useless forever. So maintain a deque of indices whose values are strictly decreasing from front to back: the front is always the current window maximum. For each new index `i`: (1) if the front index has left the window (`front <= i - k`), remove it from the front; (2) while the back element is not greater than `nums[i]`, remove it from the back; (3) push `i` at the back; (4) once `i >= k - 1`, the front is the answer for the window ending at `i`. Each index is pushed and popped at most once: O(n) time, O(k) space for the deque.

## 6. Optimal Java Code

```java
class Solution {
    public int[] maxSlidingWindow(int[] nums, int k) {
        int n = nums.length;
        int[] result = new int[n - k + 1];
        Deque<Integer> deque = new ArrayDeque<>();            // indices; values decreasing front to back

        for (int i = 0; i < n; i++) {
            if (!deque.isEmpty() && deque.peekFirst() <= i - k) {
                deque.pollFirst();                            // front index left the window (at most one per step)
            }
            while (!deque.isEmpty() && nums[deque.peekLast()] <= nums[i]) {
                deque.pollLast();                             // dominated: smaller and older than nums[i]
            }
            deque.offerLast(i);
            if (i >= k - 1) result[i - k + 1] = nums[deque.peekFirst()];
        }
        return result;
    }
}
```

## 7. Quick Revision
Keep a deque of indices with decreasing values: the front is the window max. For each new element, drop the front if it left the window, drop back elements that are `<=` the newcomer (they can never be a max again), push the newcomer, and read the front once the window is full.
Each index enters and leaves once, so O(n). A heap works too with lazy deletion (pop while the top index is outside the window), O(n log n).

## 8. Pattern
- Primary: Monotonic Deque (sliding window maximum)
- Secondary: Heap with lazy deletion, Sliding Window (fixed size), Monotonic stack family
